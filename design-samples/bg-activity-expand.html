右下角后台活动浮窗 · 展开形态 ×2

四块版面数据、文案、规则完全相同，差别只在详情长在行的哪一侧、列表谁在上，以及展开时你鼠标指着的那一行动不动。 操作：① 鼠标移到右下角小浮窗上 → 它在原地向上、向左长成详情卡；② 在三块版面里从下往上依次 hover 各条任务（尤其是最上面那条——上一轮你反馈的"展开最上行时整块缩短、鼠标掉出框外自动收起"就是这里，现在定高了不会再发生，可以来回快速扫一遍验证）； ③ 点「关闭」永久关掉那一条，全关完浮窗消失；④ 「塞进 12 项」看 8 条封顶与「另有 N 项」；⑤ 「模拟重启软件」验证关过的不再出现。

版 A · 指着的那一行是铰链（推荐）

最新那条排在最下一行，详情往它的上方长。实测：第一次 hover 小浮窗那一行 0 位移（四版里只有 A 做到）， 往上扫到别的行为下移 120px。左侧主题色竖线穿过详情块 + 铰链行，行上带书名 → 三条任务同时在场也不认错归属。 阅读顺序是反的：先看到详情、再看到它属于哪个书名行。

版 B · 常规列表（详情在行下方）

最新那条排在最上一行，详情往下方长（阅读顺序更常规）。 代价：卡片底边钉死，展开时整块向上顶，你刚指的那一行会往上跳约一行详情的高度。

版 D · 本轮新增：A 的行序 + B 的详情方位（你要的结合版）

最新那条仍在最下一行（收起态就是它），但详情长在它下方 → 阅读顺序是正的：先书名行、再详情、再按钮。 实测位移：第一次 hover 小浮窗 → 那一行上移 120px（它的详情正好填进它原先占的那块区域，光标仍在同一条 task 内、不会抖收）； 之后再往上扫 → 0 位移（比 A 好）。代价全在"第一次抬升"那一下。

版 C · 详情同时摊开（给你对比）

hover 小浮窗 → 每条任务的详情一次性全部摊开，不用来回 hover、也不存在"详情属于哪一行"的疑问。 代价全在实测数上：每条 24 + 120 = 144px → 3 条就 432px 开始要滚；封顶 8 条时内容是 1177px，被压进 418px 的窗口（≈ 只能看到三成，其余靠滚）。 这块版面已配 max-height 420px + 内部滚动，点「塞进 12 项」就能滚给它看。 A/B 同场景实测 346px、不需要滚（公式 24×N + 120，3 条 196px）。

四版共同的口径（这部分不是视觉选择，是要落进代码的规则）

  • 容器化：一任务一行，各自单独关闭。详情卡把所有待办一次列出，不再"关掉一条、暗地里顶上来另一条"。全部关完 → 浮窗自动消失。
  • 收起态一行 = 最新那条，形如 ● 书名 │ 状态文案 · 共 N 项（N>1 时才带项数），提示还有别的。
  • 每行都带书名。数据现成：播种时来自 materialTitle、会话内来自广播的 title，也就是 describeTask 里那个 heading（现在展开态才有，改成常驻行上）→ 不需要新增任何字段。空间不够时书名先省略号、状态文案不截。
  • 主题色竖线贯穿"铰链行 + 详情块"（本轮按你的要求改的）：2px 竖线常驻在每个任务左侧、未展开时透明，展开时才上色 → 一条线把摘要行和它的详情串成一块，多任务同时在场不会认错归属；常驻透明占位也保证展开瞬间零位移。竖线只上在"当前展开的那一行"，同一时刻只有一块详情。
  • 详情块左边界 24px + 竖线 2px = 26px，与铰链行的文字起竖同列（点 10 → 文字 26）→ 缩进即"这是上面那行的下级"。
  • 详情块定高 120px（本轮按你反馈的抖动改的）。原先详情块按内容自适应高度，于是：hover 最上面那条时，下面那条的详情收回 D_收、自己这条长出 D_长，卡片总高变化 D_收 − D_长；底边钉死 → 顶边整体下移 → 光标落到卡片框外 → mouseleave → 自动收起（就是你描述的现象）。改成定高后总高恒为 24×N + 120，实测切换详情时 ΔH = 0、Δ顶边 = 0，光标只会落进"自己那条的详情区"里（实测落点仍在同一条 task 的框内）。代价与校准过程：文案 3 行封顶 —— 我先按 2 行做，实测最长真实文案（被中断那条 40 字）自然高度 2.39 行会被真截断，所以块高按 3 行给到 120px（= 8 + 56 + 8 + 2 + 8 + 26 + 12，8px 网格）；进度槽恒在（进度未知时显示虚线槽而不是删掉一行，少一行就是少 10px）；收起态只留一行（行分隔线 1px×N 与「另有 N 项」那行收起时一并隐藏，否则小浮窗会被撑成 37px 而不是 26px）。
  • 8 条封顶：只显示最新 8 条（收起态那条必定是最新的，恒在），旧端折成一行 另有 N 项 · 点此全展开，点一下临时全列、再点收回。A/B 8 条时卡片实测 346px（24×8 + 120 + 分隔线与「另有」行），不需要滚动。
  • 关闭即持久化：「关闭」和「打开导图」都把 runId 写进 settings.json → activity.dismissedRuns（上限 200 条）。启动播种跳过这些 id。样张里用 localStorage 顶替，「模拟重启软件」走的就是这条判定。
  • 同材料去重：启动时每个材料只保留最新一条可续跑运行。你库里现在有 2 条 section_ready 同属一份材料（优绩主义），去重后只剩 1 条 → 一次点击就干净，不用点两次。
  • 生成结束后不自动消失 —— 更正：这一条现行代码已经满足，不需要改。我先前在此处写过「现在的代码在终态 12 秒后自行收起（activity.ts:429-431）」，那是错的：activity.ts 全文 335 行、没有任何终态定时器（grep setTimeout 只命中 BackgroundActivity.tsx:59 那个 160ms 的 hover 收起延时）。终态停留直到用户处置本来就是 activity.ts 顶部注释③的既有约定。真正要改的只有两条：关闭状态不持久 + 陈旧运行不去重。
  • 只在有任务时存在：空闲不渲染（这条测试里已有断言，保留）。正在生成的那条始终在场，不受重启/关闭规则影响。
  • 按钮口径不变：「取消任务」只给正在跑的那条；「打开导图」只给有可看版本的那条；文案与色调直接抄 describeTask。
