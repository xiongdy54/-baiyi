摘录页 · 当前实现对照组

照 src/theme.css:4381-4441 + ExtractCardFace.tsx 原样复刻，含两处真实缺陷：① .primary 在 theme.css 里没有任何规则 → 「下一条」是浏览器默认按钮（带圆角、高 23px、底色 rgb(240,240,240)）；② 头部五要素挤同一横排 → 计数不再独占右上。它的数字就是本次要消掉的差值。

三 · 五版提案（唯一争点＝动作区形态）

七栏共用同一份数据、同一套硬锚点；每栏的注释只写它自己那条差异。动作集合固定为六个： 下一条 / 推迟 / 优先级 / 毕业 / 撤销 / 返回阅读；「跳转原文」「打开摘录」按复习页既有做法留在元数据行（.review-jump accent 文字钮），不进动作区。

A · 纯文字钮一行最轻

六个动作全部降为 Meta 档无边框文字钮（与 .review-jump 同族，但用 --text-secondary，把 accent 留给「跳转原文」这一既有语义）， 用「·」分隔排成一行；主次只由字重与顺序表达（下一条 600 且居首）。整页除正文外没有第二块视觉重量——最贴合「按钮重要程度不突出」。 代价：按钮边界不可见，鼠标用户要点下去或 hover 才知道能点；推进控件实测高 18px，触控/点击目标小于桌面 32px 档。

B · 一行 32px 描边复用复习页既有档

六个动作一律 .btn.btn-sm.btn-outline（32px，与复习页 .review-tools 的「对比卡 / 标记并暂停 / 跳过 / 删除」同一档），等宽内容自适应、不拉伸。 零新构件：复习页早就用这一档放"次要但有边界"的命令，摘录页整体套用即可，新增 CSS 只有动作容器一条。 代价：六个 32px 描边框并排，边框本身的视觉重量加起来仍偏重；是否折行看量测表「动作区内容宽×行数」。

C · hairline 底栏（左次级 / 右推进）一档之差表达主次

动作区上缘一条 hairline，内部左右分栏：左＝次级命令（文字钮组），右＝唯一的「下一条」40px 描边按钮（不给 accent 填充）。 主次由尺寸差一档（32/40 与有框/无框）表达，不靠颜色、不靠等分网格。推进动作恒在最右，与 §5.3「主按钮恒在最右」一致。 代价：动作区从一行变成一条"栏"，纵向多占 hairline + padding；左右分栏使两组按钮之间的空白被读成"两个区"，需要习惯。

D · 两行分组（调度 / 导航）按语义分组

动作按语义拆两行，行首各挂一个 12px/600 大写小标签：调度＝下一条 / 推迟 / 优先级 / 毕业，导航＝撤销 / 返回阅读。 两行同取 32px 描边档，等权只发生在组内——这正是对"不该等分"的另一种回答：不是把尺寸拉平，而是把语义分开。 代价：纵向占两行（比 A/B 多 44px 一档）；标签本身是新的视觉元素，复习页没有同类先例。

E · 定高坞 + 一行 32px唯一零位移

整屏 grid-template-rows: auto 1fr auto：计数行 / 正文区（内部滚动）/ 动作坞（hairline 上缘，内装 B 档一行）。 连续处理时动作坞永不移动（量测表 Δy 应为 0，其余四版为正数），手和眼停在固定位置。 代价：与复习页的流式排列不统一（复习页评分区跟着卡面上下走）；短正文时中段留白；坞常驻会长期吃掉约 88px 竖向空间。

五 · 实测表（脚本现场量，非人工填写）

量法：每栏取 getBoundingClientRect() 减去同一栏仿窗口的矩形（文档坐标必须归零到仿窗口，否则读数不可比）。 「计数右缘差」基线取本版心右缘，不是仿窗口右缘（仿窗口有 64px 内边距，拿窗口右缘会把这 64px 混进读数）。 「动作条 Δy」＝先把当前条切到最长正文量一次，再切回最短正文量一次取差，量完自动恢复你选的条目。 「与复习页差」＝该栏读数减复习页参照读数，0 = 对齐。 「最宽一行跨度×行数」按按钮垂直中心聚簇得出（不是按 top：同一行里 align-items:center 会让不同高度的按钮 top 差 0.4px，实测把 V0 的「优先级」因 ▾ 字形误判成两行）； D 版的 2 行是设计如此，其余版出现 2 行才叫折行。 两处读数请这样理解：五版「动作条顶 y」比靶子高 118.4px，是因为摘录页没有背面答案块（内容差异，不是版式偏差）； 而靶子 Δy +319 小于五版 +351，差的 32px 正是复习页 min-height:200px 的托底——样张已在摘录栏按落地口径置 0，所以 +351 才是真实的正文位移量。 正向对照：V0 的推进控件高与「计数右缘差」必须不为 0（它现在就是错的）；若 V0 也读出 0，说明量测空转，整表作废。

六 · 规范自检（禁止清单 + Token 纪律）

检查项判据结果

七 · 落选方案与代价（含本轮被推翻的那条）

  • 【本轮推翻】把复习页的 4 等分动作网格搬到摘录页。上一轮五版共用此骨架，用户 2026-09-25 指出：四档评分是复习中最重要的元素，摘录页所有按钮的重要程度都没有那么突出。等分网格的语义是「四者同权且都是主行动」，用在摘录页会把「毕业 / 撤销」抬到与「下一条」同宽同高（实测每格 168×56px，占版心 100%），既虚增权重，又让动作区成为全页最重的一块——比正文还重。本轮五版全部改从这条出发。
  • 【本轮撤回】刻度带（元数据摊成与动作网格同列的 4 等分标尺）。依附于上面那条被推翻的网格；且看图时暴露新问题：标尺带与动作列同宽会形成上下配对，「下次推送」压在「优先级」按钮上方，容易被读成一组。
  • 【本轮撤回】左元数据栏（168px 侧栏竖排调度信息）。实测正文左缘从 190px 移到 382px（+192），「复习 ↔ 摘录」来回切时正文横移一整栏宽，与本轮「位置统一」的口径正面冲突。
  • 正文用 18px（Title S）折中。否决：复习页 26px 与它都不同，等于制造第三种字号，两页仍不对齐，只是差值从 12px 缩到 8px。
  • 右侧竖排常驻动作栏。否决：主行动落到右缘，与复习页「动作区在正文正下方、贴版心左缘起排」的位置契约冲突；且正文测量宽被压到 528px。
  • 用 accent 填充表达「下一条」。否决：摘录页唯一的高饱和焦点应当留给导航与链接（顶栏高亮、跳转原文、焦点环）；给一个每 3–5 秒就要按一次的推进动作上填充色，等于把全页最重的色块放在最机械的动作上。本轮五版一律无 accent 填充（量测表「上色全部来自 Token」行同时核对）。
  • 卡片容器（灰底 / 描边框）包住摘录。否决：复习页卡面无容器装饰；瑞士风四类卡片在此场景没有角色，hairline 与留白已足够分区（规范「网格线不可见」「克制优于炫技」）。
  • E 的定高改成「正文区高度取队列里最长那条」。否决：需要预渲染全部条目量高度或写死 min-height 魔法值，两者都会随队列内容抖动，反而制造位移。
  • 把摘录并回复习页、删掉独立摘录页。否决：合并模式下复习页要同时承担评分与摘录推进两套动作集，四档网格会被挤成八格；摘录的「正文就地编辑 + 制卡数 + 优先级」在闪卡语义里没有位置。

八 · 若要落地，属于哪一级变更

这不是纯样式改动：它改到 §5.2「页内只保留右上角计数」的执行方式、§5.3「复习页卡面 26px/1.5」是否扩到摘录页、 以及「摘录页动作区用哪一档控件」这一条全新契约。按仓库既有口径：采纳任一版都要先 bump 指南 + 登记决策号（D61 起）， 给 §6.8 补一节「摘录页排版」，并同步 tests/extract.gui.mjs 的几何断言（现有 76 步里凡按 .extract-face-actions 定位按钮的用例都要改判据）。 另外三处连带项，无论选哪版都要一起做： ① .primary 零规则 → 全仓 <button className="primary"> 都拿不到样式（本轮实测到摘录页 1 处，需普查其余页面）； ② .review-face{min-height:200px} 在摘录页短正文时会空托 119.8px（实测），落地时应显式去掉或按内容定高—— 样张已按落地后的口径把它置 0，所以量测表里的 Δy 是「去掉托底之后」的真实位移； ③ kicker 的 inline-block 同流排法与规范「对齐法则」矛盾，复习页与摘录页宜一并改为上下结构。
