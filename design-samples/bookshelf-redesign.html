你分两轮提的七处诉求：留白、拖拽排序、添加按钮上移、封面形态按钮难看、视图/密度/排序收进工具条、 空态去掉重复主按钮、以及文件夹（拖到书上成组 + 自定义命名）。逐条给了根因定位、一个可改宽度可拖拽的仿真原型、 以及按规范落地的改动清单。本页是独立样张：src/ 与 electron/ 零改动， Token 逐字抄自 src/theme.css。

2 可交互原型

仿窗口右边界可以用鼠标拖（CSS resize），也可点下方预设宽度。 工具条分段、卡片拖拽、Alt+方向键、就地改名、就地二次确认、语言下拉、目录表视图、深色模式都是真的。 预设里的 1600 会被本文档版心（1320px）夹住 —— 要看更宽的效果，把浏览器窗口拉大或直接缩放页面。

下面两项是样张自己的控件（造数据 / 看配色），不进应用； 视图、密度、排序这三项已经按你的要求搬进了仿窗口里那条吸顶工具条。

卡片类型
图注区坐在 --paper 上，灰底封面 + hairline，不叠描边（卡片四类互斥）。添加钮改回 .btn-primary，网格不再需要第四类。
拖拽态
拖动中的卡 = --accent-soft 底 + 2px accent outline（outline-offset:-1px 压在框内，不撑布局）+ 内容降到 45% 不透明度。不倾斜、不漂浮阴影、不做幽灵图；dragover 实时重排，落点即所见。
工具条
吸顶一行：计数 / 面包屑 · 视图（图标分段）· 密度（文字分段）· 排序（当前值 + 下拉）· 弹性空隙 · 拖拽提示 · 添加材料（快捷键 Ctrl+Alt+N 作钮标的一部分，不单占一格）。主按钮恒在最右，滚动时不消失。窄窗口用容器查询逐级退让（container-name:shelf，阈值按容器宽 = 窗口 − 内边距 64 − 滚动条约 15）：900 以下收起密度档、1100 以下收起提示文字、1280 以下收起三个小标签 —— 阶梯必须单调，中间档位若各回各的会在中段挤成两行（样张实测踩过 760/900 两处）。逐宽扫描 420–1620px 的结论：只有 500px 以下才出现第二行，540px 起全程单行 59px。代价说清楚：控件会消失 = 可发现性下降，所以极窄时建议默认改走目录表；要长期用窄窗就把这三档收进齿轮的「显示」区，那是另一个决策。
文件夹卡
不是一张封面，是一册带标签页的合集：顶部 12px 高的 FOLDER 标签页（paper 底 + --border-strong hairline，压住卡顶边）；中段一排书脊（最多 5 条，每条用成员的封面裁成竖窄条，成员不足 5 就少画几条，第 5 条放不下时写成 +N 的 grey-2 计数块；单条封顶 56px 并左对齐 —— 不封顶的话一本成员的文件夹会画成一大块灰板，反而不像"一排书"）；底部成员数 4 用 Title L 26 / 300 + Meta 档「本」+ 右对齐 均值 62%。图注区与书卡同规格（名称 + 4 本 · 均值 62% · 09-21），网格节奏不乱。识别度靠形状（标签页 + 多脊）而不是靠颜色：零新色、零阴影、零圆角。
文件夹 hover
整块封面区翻成 --overlay-ink 名册：顶行 成员 4 本（Meta 档 overlay-helper），下面按序列出前 6 本书名（序号 mono + 两行截断），超出写「还有 N 本，进去看全部」。底部 40px 留给动作条，两者不打架。:focus-within 同样触发，键盘用户 Tab 进去也看得到。目录表里对应地：常态那行报 4 本 · 均值 62%，悬停换成成员清单。
三区落点
拖动时目标卡分左缘 / 中央 / 右缘三区：两侧画 2px accent 竖条（重排），中央整块 accent-soft + 描边 + 「归入《X》」浮标（成组），两种意图不同形，松手才落库。文件夹内部不再给中央区（一层为限）。落地的量度修正（用户实测）：高亮框与两侧竖条都按「封面 + 2px 进度轨」这一块画（DOM 上由 .shelf-face 承载这一整块，图注文字在框外）——原先框只圈到封面底、把进度轨落在框外，看着短一截；竖条若顺着书名一路到底，同一张卡上就会出现两套高度。
空态
几何装饰 + 一句话，不再放主按钮；文案直接指过去：「用右上角的『添加材料』，或按 Ctrl+Alt+N」。需同步修订样张文档那条（见 §7）。
目录表视图
同一份数据、同一套排序能力的第二种形态：列天然填满宽度，只画横向 hairline，数字列 mono + tnum 右对齐。窗口很窄或书很多时，它比封面墙省事；把手、Alt+方向键、就地改名、就地确认、归组菜单在行内同样可用，文件夹在表里是一行带叠角的条目。

min(100%, …) 是必要的下限保护：窗口窄到放不下一列下限时，轨道不会被撑破容器。 删掉 justify-content 是因为 1fr 已经吃满剩余空间，留着它只会在极窄时留下第二条空隙。 列数由 auto-fill 按容器宽度决定，不需要 JS、不需要 @container 断点表。

6 排序、拖拽与文件夹的契约

环节定下来的做法
什么时候能拖排序 = 手动顺序（默认值）时把手在场；其余三种排序下把手不渲染，工具条给一句可点的「改回手动顺序」。不出现"看着能拖、拖了没反应"的歧义。
鼠标路径按住卡片或左上把手拖动，松手即落库。落地采信的反馈方式：目标卡进入三区态（竖条 / 整块描边 + 浮标），松手执行——与仪表盘重排一致（dragover 只记落点、不改 DOM）；样张里演示的"边拖边换位的实时重排"是同一套三区判定的另一种反馈，实现时不采用，因为 React 下在 dragover 里重排会让被拖节点身份不稳定，且实测合成事件必须分三个 tick 发才测得准（见 §7 教训）。
键盘路径聚焦卡片 → Alt+←/→（↑/↓ 同义）逐格移动，与 Dashboard.tsx:93-116 同一条语义、同一个 reorder()；aria-live 播报「《书名》移到第 3 位」。规范依据：瑞士风「键盘可达 —— 所有交互元素 Tab 可达并可完成同一件事」。
持久化settings.app.shelfOrder: string[]（SettingsStore 的 app 层）。不加数据库列：备份包本就含 settings.json（electron/backup.js:2），仪表盘布局也是同一存法（settingsStore.set("dashboard","layout")），因此 M2 备份/恢复天然覆盖，且零迁移成本。新书不在数组里时按 created_at DESC 插到队首并高亮 1.2s（样张里点「添加材料」就是演示这个落位）。
读取顺序主进程 listItems() 一行不改；渲染层按 shelfOrder 索引排序，数组外的 id 用 created_at 兜底。library/changed 的既有刷新路径（§4.2-1）保持不变。
代价（不藏着）顺序存设置而非列，好处是零迁移、备份已覆盖；代价是将来真接 AccountSyncProvider 时，id 数组的跨设备合并比"列排序"复杂（同一本书在两台设备各自被挪动）。当前是 LocalNoopAccount，不构成立即的约束；到那天把数组一次性折算成 sort_order 列即可，升级路径保留。
拖拽的三种落点拖动时目标卡按横向分三区：左缘 28% = 排到它前面（画 2px accent 竖条）、中央 44% = 归入 / 成组（整块 accent-soft + 2px accent 描边 + 浮出「归入《X》」标签）、右缘 28% = 排到它后面。两种意图长得不一样，不需要记修饰键；dragover 时实时判定，松手才落库。
成组（两本书）把 A 拖到 B 的中央 → 立刻生成文件夹，成员序 [B, A]（被落在前面的先），文件夹占据 B 原来的位置，A 从顶层移除；命名框随即弹出，回车落名、Esc 取消并解散回原位（不留下没人认领的空盒子）。
归入（已有文件夹）目标是文件夹卡时同样走中央区；书若已在别的文件夹里，就是从旧文件夹移到新文件夹——不做隐式合并（合并两个文件夹只发生在把整个文件夹拖到另一个上？不：那被禁止）。旧文件夹若空了保留并显示「空文件夹 · 把书拖进来」（标签页仍在，书脊区换成一枚 folder 图标 + 两行提示），用户数据不悄悄消失。
命名就地改名，与书名同一条 rename() 路径（图注区变输入框、Enter/失焦提交、Esc 取消、无框线）。默认名固定「未命名文件夹」——不拿目标书名自动命名，也不让 AI 起名：这是用户的组织行为，名字得他自己给（与 §1.7「AI 输出必须人工确认」同一条纪律）。
进入与返回点文件夹卡 = 进到它内部，工具条左侧出现面包屑。回顶层给三条路，不只靠一个灰色小字（第一版只留了「书架」两字，实测不够显眼）：① 最前端的 返回书架 描边钮（Lucide 左箭头 + 文字，32px，与工具条其余控件同档）；② 顶栏导航「书架」（本来就在那儿，且是 §5.2 的常驻面）；③ Esc。任一方式退出后焦点回到那张文件夹卡上，不丢上下文。同一行里不再并存第二个「书架」小字 —— 两种写法一起出现，读的人要猜哪个才是出口。这个钮兼任拖出落点：在文件夹里把书拖到「返回书架」上松手 = 移回书架。不弹模态（书架本身就是列表，再套一层窗口只会丢掉密度与滚动位置）。文件夹内继续可拖拽重排。
非鼠标路径卡片动作条的「归入文件夹」按钮打开菜单：新建文件夹并放入 / 逐个列出已有文件夹（带成员数）/ 移出当前文件夹。键盘与触屏都不依赖拖拽精度；Alt+方向键 仍然只管重排。
解散与"删除"文件夹只有「解散」和「全部移回书架」，没有「删除」——避免一次误点连着软删一串书和它们的进度。菜单里两行文字都写清结果，解散后成员回到文件夹原来的位置。
一层为限不做嵌套：文件夹不能装文件夹。理由与 §4.5「知识三层分离」同构——书架是视图组织层，多一层嵌套只让归属变模糊；要做层次请用阅读器的目录（那是材料自己的结构）。文件夹卡拖到书或文件夹的中央一律拒绝并给内联提示。
归属不是所有权文件夹只决定书架上怎么摆，不改变任何数据归属：卡、摘录、进度、领域标签仍各自挂在那本书上（library_items 一个字段都不动）；统计、今日队列、FSRS 调度、导图与记忆全部不感知文件夹。将来若要"按文件夹批量制卡/批量复习"，那是一个新单元，须先立规范。
数据落点settings.app.shelfFolders：{ folders:[{id,name,items[],created}] }，顶层 shelfOrder 里放文件夹 id 占一个条目位。与排序同样存设置、同样被 M2 备份包覆盖、零 schema 变更；渲染层负责按数组排布，主进程 listItems() 不动。
删除与软删从数组里摘掉被软删的 id（顶层数组与各文件夹的 items 都要摘，留着也无害，查询本就带 is_deleted=0）。

8 落选方案与理由

备选为什么不用
Masonry 瀑布流（按封面原始比例排）能消空隙，但行边界不齐、视觉噪声大，和 8px 基线网格正面冲突；跨列拖拽的落点也会变得难以预测。本应用封面一律按 2:3 裁，用不上真实比例带来的信息量。
justify-content: space-between 均摊余数空白改由列之间承担，卡片间距随窗口宽度连续变化，等于把"右侧一条空白"换成"间距不守 Token"。网格间距必须是常量。
定宽卡片 + 整块居中违反瑞士风「左对齐 + 非对称留白」；书架是内容面，不是 720px 单列版心，居中会让计数与工具条一起漂移。
整块封面继续做点击靶 + hover 黑幕（现状）黑幕一闪就把身份（封面）整块抹掉，书名、进度、语言、操作全挤在同一层，是"难看"的直接来源。图注卡把常驻信息与临时操作分层，读起来稳定得多。
卡片上常驻按钮行每格 4 个按钮 × N 本书，工作区噪声大，违反「装饰克制、工作区保持纯净」。保持 hover / focus 显形 + 键盘可达。
新增 sort_order 数据库列要迁移、要改 listItems() 的排序口径、要接进备份一致性验证；相比"存设置"没有多给任何当下需要的能力。列为向 M11 / 云同步演进时的升级项。
把「添加材料」放顶栏右侧§5.2 锁定顶栏右侧只有设置齿轮 + 窗控三键，且顶栏是 drag 区。工具条才是它该在的位置。
点文件夹弹出模态窗口列成员书架本来就是列表，再套一层窗口只会丢掉密度、滚动位置与吸顶工具条；面包屑 + 就地换列表能沿用同一套卡片与拖拽代码。
自动用目标书名当文件夹名 / 让 AI 起名成组是用户的组织动作，名字得他自己给；自动命名会造出一堆"看起来不用改"的名字，反而没人再改。折中：默认「未命名文件夹」+ 成组瞬间弹出输入框，命名只多一次回车。
文件夹多层嵌套见 §6「一层为限」。真需要层次就用阅读器目录——那是材料自带的结构，不该在书架上再编一套。
加修饰键才进入归组态（如按住 Alt 拖）要背、要在拖拽中途改键盘状态（浏览器 drag 期间拿不到可靠的 modifier 变化），且看不到反馈。三区分命中是"看得见的手势"，代价是中央区要够大——200px 卡的中央 44% 约 88px，够用。
空态仍保留「添加第一本书」你已否掉：与工具条主按钮同屏两个主行动。这里不是把代码改回去，而是把样张文档那条「空状态含一个主行动」修订掉（§7 已列）。

9 交付前自检（瑞士风七条 + 五项必查）

检查项结论说明
单一焦点色通过界面只有 IKB 一档 accent：进度轨、selected 态、拖拽态、主按钮同一来源。占位封面的 accent 色块属内容层（真实封面是图片），不计入界面焦点色；本样张全程不出现第二支高饱和色，error 只在删除确认与"富余非 0"标注里作状态用。
极致字号对比 / 越大越细通过样张标题 44/300，卡片书名 14/500，meta 12/500-600。工作区不放 Display 大字。
无衬线通过chrome 全部 --font-sans，无衬线出现（阅读正文的衬线例外不涉及本页）。
直角、零渐变通过--radius 恒 0；全页无 linear-gradient。阴影只出现在两处合规位置：语言下拉浮层的 --shadow-float，以及"留白可视化"切片里当内容底色的用法。
8px 网格 / hairline通过间距全取 Token；2px 一律 calc(var(--sp-1) / 2)（本样张起别名 --hair，落地时按 §5.3 直接写 calc）；1px 只作描边与分隔线。
克制优于炫技通过空态几何装饰不外溢进工作区；卡片不做倾斜、漂浮、玻璃。
深色模式已试切「深色」查看：accent 走 #5b7fe8 提亮档、--accent-on 换纯黑；动作条 --overlay-ink 为固定深色层，两种主题下文字对比都不依赖主题反转。实测主按钮底色随 body.theme-dark 的 --accent 正确翻转（隐藏页里 CSS transition 不走时，getComputedStyle 会读到旧值，得触发一次重算才看得到新值 —— 真机切换不会残留旧蓝）。
键盘焦点可达已试卡片、四个动作、语言下拉项、工具条分段、主按钮全部 Tab 可达；:focus-visible 为 2px accent 环 + offset 2px；Alt+方向键 在卡片上完成与拖拽同一件事（把手只做鼠标的视觉提示，aria-hidden + tabindex="-1"，不占 Tab 序，键盘路径不依赖它）；:focus-within 让动作条显形（不用 visibility，按钮保持可聚焦）。
文字不小于 11px通过全页最小为 Meta 12px。
无字符充当图标 / 无 emoji通过图标一律 16/20/24 内嵌 Lucide 路径、stroke 1.5、currentColor；窗控三键是 SVG 图元；文档正文里的方向键符号用 HTML 实体写在 code 语境，界面上不出现 × / ⋮ / ✓ 之类字符。
无硬编码魔法值通过色 / 字号 / 间距 / 层级 / 阴影全走 Token；结构层 CSS 实测零彩色字面量（#hex / rgb() 只出现在开头的 Token 声明块里）。三档密度是 --shelf-min 的三个取值，属 Token 而非裸写值。Token 块整份抄自 theme.css，含深色档与零消费者的预留档（--shadow-panel / --radius-pill 等），样张不删减，便于与落地时一字对照。已按 §5.1 的配方跑过「var() 引用集 − --x: 声明集 = 空集」，43 个引用无一未定义。
卡片四类不混用通过图注卡为灰底 + hairline，不叠描边；表格只画横向 hairline、末行不画线；主按钮 accent 填充，破坏性确认才用 error 填充。
页内不重复导航文字通过按 §5.2，内容区不设「书架 / SHELF」大标题，工具条左侧只留计数（顶层 11 本 · 1 个文件夹，进文件夹后 2 本 + 面包屑）。进了文件夹就不重复列已归组的书，总数由文件夹卡上的 2 本 自己报。
空态只有一个主行动通过（需同修订规范）空态按你的要求只剩几何装饰 + 一句话，主行动由吸顶工具条承担。这与 swiss-international-style.md「状态设计 · empty」「布局模式库 · 空状态」现写的"几何装饰 + 一句话 + 一个主行动"字面冲突，落地时须一并补上"主行动已在吸顶工具条常驻时不重复"的例外，见 §7。
prefers-reduced-motion通过样张末尾统一关闭过渡；落地时同步删掉 .card-acts 与新按钮的 transition 项。
对齐法则通过工具条与网格共用同一左右内边距 --sp-8，子元素不再叠加水平 padding；卡片之间只用 grid gap，不逐个写 margin。
密度档位不混档通过工具条内所有控件同取 32px（分段钮、排序下拉、主按钮 .btn-sm），与顶栏的 32px 导航同档；40px 只留给模态与页面级表单按钮。规范允许"个别数据密集页局部降为 compact"，本条按同一档走完整条工具条，不在同一行里混 32 与 40。
命中区尺寸已量三区命中在标准档（200px 卡）下：左/右缘各 56px 用于重排，中央 88px 用于归组；紧凑档（152px）下中央仍有 67px。卡片动作钮 28×28 与现状一致，桌面端可接受（规范的 44×44 是移动端底线）。归组中央区取"宽 > 两侧之和"是有意的：成组是更省力的默认，重排才需要贴边。
文件夹卡不引新语言通过识别度全部靠形状：标签页 + 一排书脊 + Title L 档成员数，色值只用已有的 --grey-1/2、--paper、--border-strong、hover 名册沿用书卡同一块 --overlay-ink。零新色、零阴影、零圆角、不用 emoji、不引第二焦点色。文件夹只有解散与移回书架，没有删除，破坏性色（--error）仍只出现在真删书那一处。
状态可退出通过进了文件夹必须出得来：显式「返回书架」钮 + 顶栏「书架」+ Esc 三条路，退出后焦点落回那张文件夹卡（aria-live 同步播报）。同类问题一并修掉的还有工具条计数把「2 本」+「 本」拼成「2 本 本」——整串（含单位）现在由一处脚本出，HTML 里不留裸单位。
组织层不污染数据层通过样张里文件夹只影响排布与显示，进度、语言、上次阅读文本都仍挂在书上；library_items / FSRS / 今日队列 / 统计口径零改动（§6「归属不是所有权」）。

10 一句话结论

建议分两批：第一批留白（一行 CSS）+ 卡片改图注制 + 工具条收纳视图/密度/排序 + 空态去重复主按钮 —— 纯表现层，当天可见收益；第二批拖拽重排与文件夹（三区落点、就地命名、面包屑、解散语义）—— 交互与组织层， 按 §8.2 的口径须先 bump 指南 v48.15 + 登记 D51 再动代码。两批都不碰数据归属：文件夹只是书架的摆法。
