# Task 7 report — reader location preserved across the dock reflow

## What landed

- **Transient reflow guard (Reader).** `toggleSidebar` snapshots the location and arms an
  in-memory guard before the width changes; `handleEngineRelocate` consumes layout-generated
  relocates without writing progress. The guard has three deterministic exits: a real user gesture
  (`wheel` / `pointerdown` / `keydown` immediately ends it, so the user's own scroll saves normally),
  the bounded fallback (3 s), and any explicit user navigation (`turnPage`, `jumpToMark` clear it
  first). Nothing is persisted and no settings key was added.
- **PDF page-point snapshot/restore.** New optional kernel capabilities
  `captureViewPoint?()` / `restoreViewPoint?(point)` on the PDF adapter: the snapshot is the current
  page plus the point where the viewport's top-left corner falls inside that page's **content box**
  (same reference frame as `sourceAnchor.rects`); the restore scrolls that point back to the corner.
  Fit presets are intentionally left to pdf.js and only require page continuity.
- **Restore policy.** Numeric zoom → restore the page point two frames after the width change (no
  relocate is generated by a pure width change). EPUB → restore the saved CFI on the first reflow
  relocate. Both run once per toggle.

## Findings (recorded honestly)

- **pdf.js only re-fits on `window` resize.** Opening or closing the dock narrows/widens the engine
  container without a window resize, so `page-width` / `page-fit` keep their scale and the page is
  simply cropped/scrolled (measured: container 968 → 1268 px, page width 927.6 px unchanged). The
  contract therefore asserts only container widening + preset retention + current page; the page
  width readings are printed as evidence. This matches the pre-existing behaviour (the old left dock
  used host padding and did not re-fit either), and forcing a re-fit would be a behaviour change the
  plan does not authorize.
- **Suppression must outlive the restore's own settle relocates.** An earlier revision cleared the
  guard on the first relocate after the restore and leaked one progress write during the window
  (measured ratio 0.16076 → 0.16575). The guard now holds through the settle and ends on gesture or
  the bounded fallback — after the fix, a 400 ms poll over the whole open+close window reports no
  change at all (`firstChangeMs: -1`).
- **A small ratio shift is inherent** to a reflow (the same CFI can land at a slightly different
  scroll fraction); the contract is anchor preservation — same chapter CFI, same re-resolvable text —
  which is what the assertions check.
