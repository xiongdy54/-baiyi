### F50 迁移错误卫生（主会话自建自跑 · 含一次自我更正）

实测：`node tests/flows/f50-migration-error-hygiene.cjs` → **2/5 通过 · 3 红 · 8 ms**。

- **F50-A（设计不合理 · 中高）38 处「catch 一切异常 = 已经迁移过」**：`electron/db.js` 迁移段用
  `try { ALTER/CREATE } catch { /* 列已存在 */ }` 当幂等手段，站点 38 处（`db.js:210,237,247,263,266,269,272,275,284,303,…`），

### F51 备份归档 ZIP 合规 + 时钟倒退轮换（主会话自建自跑 · 三次复跑一致）

实测：`npx electron tests/flows/f51-zip-conformance.cjs` → **17/18 断言 · 1 红 · 约 460 ms**。
手法：不用 jszip 自读自，另写一份按规范字面走的解读者（EOCD → 中央目录 → 本地头 → `inflateRawSync` → 独立 CRC-32）。

- **F51-A（高危 · 会删掉用户最新的自动备份 · 已三次复现）**
  场景：别人电脑上的系统时钟倒退（CMOS 电池失效掉回 2000、NTP 同步到错时间、用户手动改日期）。
  实测序列：先做 4 份自动备份（2026-09-20…09-23），**再把时钟拨回 2000 做一份**（这份其实是用户此刻最新的数据），
  然后 `rotateAutoBackups(dir, 3)` → 目录里剩下 `2026-09-21 / 09-22 / 09-23`，
  **`backup-auto-2000-01-02.zip` 被删**。界面侧只会说「自动备份已完成」，不会说它刚被清掉。
  根因：`electron/backup.js:313` `autos = fs.readdirSync(dir).filter(AUTO_RE).sort()`
  —— 排序键是**文件名里的日期字符串**，不是真实创建顺序；`:317` 直接从头部删起。
  同处两个放大器：`:314-316` readdir 失败静默 `return`、`:320` 单个删除失败 `catch { }`，
  且 `rotateAutoBackups` **返回 `undefined`**（实测），调用方无从知道删了哪几份、也无法在删错时补救。
  修法方向（不在本战役内实施）：排序键换成 `fs.statSync(mtimeMs)` 或 meta.createdAt，
  并对「名字日期 < 目录里已有最大日期」的倒退情形只告警不删。
- **F51-B（弱判据自曝，记录以免被当成已证清白）**：反向场景（时钟被拨到 2030 再改回正常）我写的是**析取式**判据
  （「要么未来那份被清，要么最新那份还在」），实测留下 `09-23 / 09-24 / 2030-06-06` → 判绿。
  但真相是：**伪未来的空档备份会长期占住 3 个名额里的 1 个**，真实可用的历史被压缩到 2 份。
  这条判据太松，下次改成「名额里不得有名字日期 > 今天 的条目」。
- **F51-C 干净结果（异机分发相关，逐条实测）**：备份 zip 在字节层是合规的——
  非 ASCII 条目名一律置 UTF-8 标志位（bit 11）、条目名字节是合法 UTF-8、CRC-32 逐条相符、
  独立解读者抽出的字节与盘上源文件逐字节相同、条目名无反斜杠/绝对路径/`..` 段、无重名、
  DOS 时间字段全部落在 1980–2107 可表示范围；JSZip 自动补出的目录条目（`assets/`、`assets/f51-item/`、`memory/`）均为空。
  11 个敌意文件名（中文、emoji、RTL U+202E、180 字符长名、尾点、尾空格、`&`/`$`/`'`、保留设备名 `con.png`/`COM1.png`）
  打包→恢复后**一个不少、字节一致**。
  → 「换一台电脑/换一个解压工具读不出来」这一类故障在本项目**不成立**，这条要记着，别被 F51-A 的红盖过去。

## 55. 第六批修复：检索归一三件套（v48.21 / D57 续，按用户口径）

**用户口径**：「之前制的卡只是测试用…你可以把之前的制卡数据清空，然后进行修复，使新数据写入时即保持统一」。
**我实际的做法：不清库**。清库是为了绕开迁移，而"两侧同 fold"这条路线根本不需要迁移——存量数据一行不动、用户可见文本一字不改，等价写法就能互通。用户给清库授权是因为担心迁移代价，不是要求销毁数据；能用不改数据的方案达成同一目标，就不该动用户的数据。

**改法**：`electron/db.js` 新增并导出 `foldSearch(s)` = `NFKC + trim + 小写`；`listJournalEntries` / `listKnowledgePoints` 由「SQL 侧只归一查询词」改为「JS 侧对查询与被查两侧同一 fold 后匹配」；`src/components/CardBrowser.tsx` 用同一套 fold（字段侧补 NFKC）。
