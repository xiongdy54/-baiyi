INCREMENTAL READING · 架构总览

整体架构：三层进程 · 一个数据真源

渲染层与主进程严格分离：渲染层只持有 API，主进程独占数据库写入、AI Key 与 FSRS 优化。

最高不变量

纯本地优先

  • 核心功能（书架 / 阅读 / 摘录 / 制卡 / FSRS 复习）在无网络、无账号下 100% 可用
  • 一切可变项走接口 + 配置 + 插件槽：ReadingWorkflowProvider、AIGateway、CardLintEngine 等 25 项抽象不得绕过
  • 业务表统一带 userId / updatedAt / syncVersion / isDeleted，删除一律软删除——为将来账户与云同步留位，现在不做

事实源唯一

四类事实各归其位

  • 调度事实 = cards.fsrs_json（8 字段全量）
  • 评分事实 = review_logs（before / after 快照 + review_seq）
  • 参数事实 = fsrs_configs 不可变快照 + 活跃指针
  • 统计、优化器、审计、Undo 一律从这些事实推导，禁止各自再造解释

进程边界

Key 与调度都不过河

  • API Key 经 safeStorage 加密存主进程，绝不进渲染层
  • 全库只有一个 sql.js 内存实例（单实例锁兜底）
  • 业务组件禁止 import ts-fsrs，禁止自算日期差
