算法结构：FSRS 调度的事实链与不变量

调度算法本身是库的事；这个项目真正难的是「同一份复习事实不许有两套解释」——四张表、三条不变量把这件事焊死。

四类事实

一份复习只允许一种解释

  • 调度事实 = cards.fsrs_json（8 字段全量持久化，下轮全量回填）
  • 评分事实 = review_logs（fsrs_before/after_json + leech_before_json + review_seq）
  • 参数事实 = fsrs_configs 不可变快照（21 维权重 + 全部调度 option，config_fingerprint 唯一）
  • 时间事实 = reviewed_at + review_seq；撤销事实 = 快照恢复

为什么关掉 fuzz

预览值必须等于算法真实值

  • enable_fuzz = false 是产品策略，不是 FSRS 算法要求
  • 预览与实际落库同源：评分时直接复用预览算好的完整状态
  • 过期预览判废：提交时源卡不符则现场重算，禁止复用
  • 参数只影响未来调度，绝不回算存量卡片的 S / D / due

撤销与优化器

两个最容易被做错的地方

  • Undo 不变量：review_seq 最新 ∧ 有 before+after 快照 ∧ 当前卡 8 字段全等于 after
  • leech 回退恢复 leech_before_json 确切前置状态，禁止用「当前 suspended」推断
  • 优化器只从事实训练，样本过滤（单次复习 / 全同日 / 无跨天间隔）防底层 panic
  • 训练 / 应用 / 重置全部走不可变快照 + 指针，失败返回 {ok:false} 而不阻塞调度
