## 0. 用户原话与方向修订

### 0.1 最初需求

> 「从图中可以看到，当前的结构图打开之后，窗口大小的限制导致图谱展示总是不完整。我在想，可不可以把这个窗口变为完全透明，仅展示图谱，并且窗口大小要根据图谱的大小自动变大或缩小，使图谱内容始终能完整显示出来。也就是说，打开结构图后，只能看到图谱，窗口背景完全透明。但我又考虑到，这样做可能会导致结构图窗口的样式与整个软件界面的样式设计不匹配。请你先帮我想一个比较好的设计方案。最好能实现炫酷高级的图谱展示效果，同时又不破坏连贯的软件整体体验。」

### 0.2 2026-10-21 样张复核后的修订

> 「看了效果之后，我觉得暂时不需要：描边、穿透、检视框、点击节点后出现的悬浮选单。这个悬浮选单上的按钮放到控制轨上面，即那个自动隐藏的控制轨的居中位置。需要纸片底，并且需要根据图谱的收缩或展开，自动调整纸片底的大小。此外，我没看出来这个『角标』选项是什么意思。」

这次修订把方案从「全透明悬浮」改成「**纸片图谱**」：

| 项 | 初版 | 现版（2026-10-21） |
| --- | --- | --- |
| 窗口背景 | 全透明，只有图 | **必需纸片底**：94% 纸 + 1px 发丝线 + `--shadow-float`；纸片就是窗口表面 |
| 纸片尺寸 | 可选 | **随图谱收缩/展开自动变**；窗口 = 内容 + 固定留白，纸片 = 窗口 |
| 描边（casing） | 边线/关系字加纸色描边 | **删除**；纸片底取代它作为可读性基座 |
| 穿透（锁定） | 置顶 + 可锁穿透 | **删除**；窗口始终可交互，不做 `setIgnoreMouseEvents` |
| 节点浮条 | 选中节点旁浮出动作条 | **删除**；四个动作移到控制轨居中位置 |
| 角标（corner ticks） | 悬停时内容边界四角的 8px L 形裁切标记 | **删除**。它只是「这张图被放在这里」的纯视觉提示，没有交互；用户看不出用途，不保留 |
| 检视框 | 样张里的虚线测量框 | **删除**。它从来不是产品功能，只是样张的测量辅助；为免误解，从样张一并移除 |
| 解释 | 节点旁纸片浮层 | **保留**；从控制轨下方展开纸片卡，窗口尺寸不变 |

> 用户用的是「暂时不需要」：本次不保留这些代码/开关；将来若要恢复，按新决策号重新立项，避免首版留死开关。

> **2026-10-21 选中态追加修订（用户复核选中截图后）**：
>
> 「被选中的节点不要出现像图片中这样的大框套小框的样式，而是把这个节点以主题色样式强调出来，就像左边这个『论点村上隆的美术史对比』这个节点一样。修改好之后，请把你的样张的规格写清楚，避免出现之前反复出现的做出来的效果与样张不匹配的情况。」
>
> 落地：删除 `.sel-ring` 外圈；选中节点 = 整卡 `--accent` 填充 + `--accent-on` 文字，与根/阅读节点同款；规格固定在本文件 **§7.7**。

### 0.3 主场景与次场景

- **主场景**：纸片图谱悬浮在**正在阅读的阅读界面**之上。阅读正文是地面；纸片是窗口表面，不是壁纸。
- **次场景**：用户把阅读界面最小化，专注看图谱。样张另做浅色 / 深色 / 花哨三组壁纸，用来看纸片底、深色主题与阴影是否站得住。
- 两个场景共用同一套窗口尺寸、纸片、控制轨与动作；壁纸不是默认背景，只是「阅读界面不在场」时的极端测试。

## 1. 目标与非目标

### 1.1 目标

1. 结构图窗口的**内容边界**决定窗口与纸片大小；不再出现「图比窗口大、被裁掉」。
2. 静息时只有一张贴合图谱的纸片：没有标题栏、边框按钮、底部详情；纸片本身就是窗口表面。
3. 控件随需出现：上缘悬停出控制轨；选中节点后，四个动作在控制轨**居中**出现；解释从轨下展开。
4. 纸片底随图谱收缩/展开自动变大小；不是固定底板。
5. 与软件整体连贯：同一套纸/墨/单焦点色、同一套字号、同一套 1px 发丝线/直角/无阴影（纸片阴影是浮层唯一豁免）、同一套生长动画。
6. 「高级感」来自结构、动线与精度：窗口绕阅读节点生长、纸片贴合内容、控制轨自动隐藏、动作就在轨上。

### 1.2 非目标

- 不改完整图谱页签（`MindmapCanvasV2` 的整图行为保持）。
- 不新增数据库字段、AI 调用、设置键、调度逻辑。
- 不做点击穿透 / 锁定；不做多结构图窗口；不做窗口位置跨重启持久化。
- 不做手动拉拽窗口尺寸（尺寸由内容驱动）。
- 不把样张里的「壁纸切换」「尺寸账本」「常显控制轨」搬进产品；它们是设计辅助。
- 本次不做描边、角标、检视框、节点浮条、穿透/锁定；将来若恢复，按新决策号重新立项，不在首版保留死开关。

## 2. 现状与硬约束

### 2.1 现状

- `electron/lensWindow.js:69` 当前是 `width: 520, height: 660, resizable: true` 的无边框窗口；`reveal()` 在每次呼出时把背景设成主题纸色（`lensWindow.js:211`）。
- `src/components/reader/MindmapLens.tsx:562` 是「标题行 + 画布 + 底部详情」的纵向面板；底部详情在 `:656`，动作在 `:680`。
- `MindmapCanvasV2` 的 `fitTo`（`src/components/reader/mindmap/MindmapCanvasV2.tsx:211`）在容器里按 `(W-48)/(H-48)` 适配；宽图在窄窗里会低于 `FIT_MIN` 后按宽度裁切。
- 卡片尺寸上限 320×48、根卡 400×56（`src/lib/mindmap/v2/measure.ts:21`）；网格间距 16、树/论证 20–56、时间线 24。宽图（时间线/论证）是裁切的主要来源。
- `src/theme.css:9628` 的 `.lens-root` 填纸色，`:9639` 的 `.mm2-focus` 填纸色；标题行是拖动区（`:9637`）。

### 2.2 Electron 透明窗口的硬限制

1. **透明区域仍然吃鼠标点击**：本方案不做穿透；窗口矩形内会拦截点击。纸片是可见的实体，用户可拖动/关闭；这是接受的行为。
2. **透明窗口不能依赖系统原生缩放**：`resizable: false`；尺寸由主进程 `setBounds` 程序化驱动。
3. **无边框窗口放大有已知黑边**（D198，Electron 31 / Chromium 126 的 ANGLE D3D11 + DirectComposition 合成缺陷）。D198 已评估升级 Electron 42 并回滚；本方案不升级 Electron，先用 spike 验证透明窗口下 `setBounds` 是否复现，再决定窗口/纸片边缘是否做缓动。

其他：`transparent` 依赖 DWM（Windows 10/11 默认满足）；纸片的 94% 透明需要窗口本身透明；开发者工具打开时窗口会变不透明。这些写入验收与风险。

## 3. 设计主张

**窗口是图的边界，纸片是图的表面。**

- 窗口尺寸 = 图的布局边界 + 固定留白；纸片 `inset: 0`，所以纸片永远与窗口同尺寸。图谱收缩/展开 → 窗口变 → 纸片跟着变。
- 纸片不是固定面板，也不是「背后的一层底」；它是窗口本体。静息时用户看到的是一张**刚好包住图**的纸。
- 连贯性靠图谱本身的材质：纸色卡片、墨色文字、单一深绿 accent、15/13/11 字号、1px 发丝线、直角。纸片的 1px 边框与 `--shadow-float` 是浮层语义。
- 控制轨是纸片上缘的一条可隐藏轨道；选中节点后，四个动作在轨的**居中位置**出现。动作不再贴着节点，界面更安静。
- 高级感是**因果**的：纸片围绕你正在读的节点生长；新分叉从父节点长出来；纸片边缘跟着落位；不是发光、毛玻璃或霓虹。

## 4. 交互

### 4.1 静息

- 只有图谱与纸片。没有标题栏、底部详情、按钮；纸片的 1px 边框与阴影定义边界。
- 阅读节点仍是主题色整卡；其他节点纸色卡片 + 1px `--b2` 描边；根节点/阅读节点用 `--accent` 底 + `--accent-on` 字。
- 边线 1.2px、55% 墨色；**不加 casing**。纸片底是统一的可读性基座；关系字与时间字直接填 `--t3`。

### 4.2 控制轨（上缘悬停）

- 指针进入纸片顶部 **48px**（含 32px 轨净空）才浮出控制轨；在画布中部拖动/平移不会闪控件。
- 控制轨是一组**纸色胶囊**，不是整宽栏：
  - 左：6 点 grip + 「结构图」；这是窗口拖动区。
  - **中（居中）**：
    - 未选中节点时：版式标签（如「论证图」）。
    - 选中节点后：`跳到原文` / `它在说什么` / `深挖` / `在完整图谱中打开`，在轨内水平居中。
  - 右：`置顶` / `×`。
- **窄窗文案**：窗口宽 < 520px 时，动作自动缩短为 `原文` / `解释` / `深挖` / `全图`；`title` 与 aria-label 保留完整文案。7 卡树（448px）实测不重叠。
- 选中节点时控制轨**自动亮 2.5s**，让用户看到动作；之后自动隐藏。指针在上缘时保持；`Tab` 进入时保持。
- 首次呼出控制轨自动亮 1.6s 后隐去，教一次「上缘有控件」。
- `Esc` 收起窗口。
- 控制轨的标题胶囊是 `-webkit-app-region: drag`；按钮显式 `no-drag`。
- **没有角标**：内容边界不再画 L 形裁切标记。

### 4.3 选中节点

- 单击节点 = 选中：整卡 `--accent` 填充 + `--accent-on` 文字，与根/阅读节点同款；**不画外圈、不叠第二圈描边、不保留纸色内芯**。双击 = 跳到原文（沿用现有语义）。
- 动作只出现在控制轨居中位置；**没有节点旁浮条**。
- `它在说什么` → 从控制轨下方展开纸片解释卡：
  - 宽度 `min(420, winW - 32)`；水平居中；顶部 y = 36；max-height = 窗口高 − 52；超出滚动。
  - 卡头：`它在说什么` + 节点标题（截断）+ `收起`；正文 12px/1.7。
  - 卡片覆盖图谱的一部分；关闭即恢复。**不因解释打开而改窗口/纸片尺寸**。
  - 解释卡在 1129×160 的 12 卡聚焦窗里实测 420×107，底边不出纸片。
- 浏览别处时保留「回到正在读的段落」；跳到原文后保留「回到刚才读的位置」。两者是纸片左上角、控制轨下方的小胶囊（T3 实现；样张未画）。
- `深挖` 在动作按钮上显示进行中状态；`在完整图谱中打开` 走现有 IPC。

### 4.4 加载 / 空态

- 图还没就绪：一张 **320×200 的种子卡**（纸底、1px 发丝线）：`正在读取原文 i/n` + 2px accent 进度线。
- 种子窗 = 卡 320×200 + 左右 16 / 上 32 / 下 16 = **360×248**；它比「有图后的最小窗 360×160」高，因为空态卡本身占 200。
- 图就绪后，窗口从种子尺寸长到内容尺寸；纸片随之；避免白闪和「先大后小」。
- 无图 / 篇幅过短 / 需要生成：种子卡换成对应文案与按钮（沿用现有 `needsGenerate` / `scopeStreaming` / `feed.unsupported` 判定）。
- 错误与提示：纸片左下角一条纸色状态条，4s 自动消失；错误可停留更久。

### 4.5 不做穿透

- 没有锁定、没有 `setIgnoreMouseEvents`、没有「已锁定」徽标、没有主窗口「解锁结构图」。
- 窗口矩形内仍会拦截点击；纸片是可见的实体，用户通过拖动/关闭解决遮挡。这是本次明确的取舍。
- 因此主窗口最小化/隐藏/关闭时不需要自动解锁；`hide()`/关闭/退出只做原有的状态复位。

## 5. 尺寸分级算法

### 5.1 常量与留白

| 常量 | 值 | 说明 |
| --- | --- | --- |
| 左右留白 | 16px × 2 | 图与纸片边界之间的空气 |
| 上留白 | 32px | 控制轨净空（轨高 24 + 8 空气） |
| 下留白 | 16px | 与左右一致 |
| 图窗最小 | 360 × 160 | 有图后的最小窗口/纸片 |
| 空态种子窗 | 360 × 248 | 卡 320×200 + 留白 |
| 工作区上限 | 92% | 当前显示器 `workArea` 的 92% |
| 可读下限 | **0.62** | 低于此值走聚焦，不再继续缩 |
| 聚焦上限 | 按「可见子项数」从多到少试排 | 取第一个 s ≥ 0.62 的 N |
| 展开全部 | 显式覆盖 | 允许 s < 0.62，窗口仍不超过 92% 工作区 |

> 留白**不参与缩放**；纸片 = 窗口表面，所以纸片尺寸永远等于窗口尺寸。错误做法是 `window = (content + padding) * s`，这会把留白也缩小，导致内容 + 固定留白反而超出窗口；样张首轮实测就踩到过（12 卡聚焦窗口高 141px）。正确解是：

```text
contentW/H  = 图谱 layout bounds（100%）
maxW        = floor(workArea.w * 0.92)
maxH        = floor(workArea.h * 0.92)
sFit        = min(1, (maxW - 32) / contentW, (maxH - 48) / contentH)
```

### 5.2 三档 + 显式全图

| 条件 | 窗口/纸片 | 缩放 | 显示 | 用户可做 |
| --- | --- | --- | --- | --- |
| `sFit ≥ 1` | `content + 32 × content + 48` | 1.00 | 全部 | — |
| `0.62 ≤ sFit < 1` | `content × sFit + 32 / 48` | sFit | 全部 | — |
| `sFit < 0.62` | 聚焦后的内容 + 32 / 48 | ≥ 0.62 | 当前阅读分支 + 「另有 N 项」 | 点「另有 N 项」→ 全图 |
| 「展开全部」 | 92% 工作区上限 | sFit（可 < 0.62） | 全部（字小） | 「回到聚焦」 |

窗口/纸片最终钳制：

```text
winW = min(maxW, max(360, floor(contentW * s + 32)))
winH = min(maxH, max(160, floor(contentH * s + 48)))
```

### 5.3 聚焦怎么选

- 从现有 `lensGraph` 出发（父链截断 + 用户折叠覆盖），不修改用户的 `overrides`。
- 聚焦是**派生视图**：保留阅读节点、其祖先链、当前选中节点；其余分支折叠。
- 可见子项数 N 从「全部 − 1」往下试：`N` 个子节点 + 一张合成的「另有 N 项」卡；每次用真实 layout bounds 算 `s(N)`；取第一个 `s(N) ≥ 0.62` 的 N。
- 至少保留阅读节点、直接父节点与 1 个兄弟；N=1 仍放不下时按 0.62 渲染，窗口钳到 92% 工作区，并允许画布平移（极小工作区的兜底）。
- 「展开全部」= 用完整内容重排，`s` 允许低于 0.62；纸片左下角出现「全图 · 0.46× / 回到聚焦」模式胶囊。再次点当前预设页签也会回到聚焦。

### 5.4 样张实测（舞台 1228×811，1568×896 视口，含 340px 账本栏）

| 预设 | 全图内容 | 默认档位 | s | 窗口 = 纸片 |
| --- | --- | --- | --- | --- |
| 真实样张（根 + 2 证据 + 其余 6 段） | 536×168 | 100% 完整 | 1.000 | 568×216 |
| 4 卡时间线 | 764×156 | 100% 完整 | 1.000 | 796×204 |
| 7 卡树 | 416×456 | 100% 完整 | 1.000 | 448×504 |
| 12 卡论证 | 2400×152 | 聚焦 8/12 | 0.639 | 1129×160 |
| 12 卡论证（展开全部） | 2400×152 | 全图（显式） | 0.457 | 1129×160 |
| 窄舞台 760×715 下的 12 卡论证 | 2400×152 | 聚焦 5/12 | 0.639 | 699×160 |

## 6. 落位、锚点与窗口生命周期

### 6.1 首次呼出

- 仍优先贴主窗口右侧（gap 16）；右侧放不下退左侧；再放不下退当前显示器工作区右缘。
- 首次 show 用种子尺寸（360×248）出现在目标位置，图就绪后长到目标尺寸；纸片随之。
- 使用主窗口所在显示器的工作区；之后使用窗口中心所在显示器的工作区。

### 6.2 生长锚点

- **纸片围绕阅读节点生长**：以阅读节点（或当前选中节点）的中心为屏幕锚点；尺寸/缩放变化后反算窗口原点，让锚点尽量不动。
- 非贴边时锚点漂移目标 ≤ 8px；贴边导致原点被钳制时，记录实际漂移并标注「边缘钳制」，不视为失败。
- 样张实测：12 卡聚焦切换时漂移 40.5px（右缘钳制）；全图 → 回到聚焦 0.33px；窄舞台 760×715 下 190px（纸片几乎占满舞台，必然钳制）。
- 内容变化 debounce 80ms；拖拽/平移过程中不 resize，`pointerup` 后再落位；隐藏时不 resize。

### 6.3 成长方向

- 优先向**远离主阅读窗口**的方向长；到工作区边缘再向回长。
- 如果没有空位（主窗口最大化），允许叠在主窗口上；纸片是可见实体，用户可拖动/关闭。
- 窗口位置不做跨重启持久化；每次呼出仍按「贴主窗口右侧」重新落位（与 D197 一致）。

### 6.4 窗口生命周期（保留 D200/D202 纪律）

- 关闭 = 隐藏（单例复用）；真正退出才销毁。
- `did-start-loading` 复位 `loaded`；`ready-to-show` 幂等消费挂起呼出；`did-finish-load` 兜底；2s 安全阀；`hide()` 取消挂起。
- 完全离屏（与所有 workArea 零交集）时 `show` 重新贴回工作区。
- 每个阅读会话从「关」开始（D202），不随阅读会话自动弹出。
- 主题/皮肤仍由 `theme.css` + 皮肤桥一处改两窗同步；窗口背景保持透明（纸片的 94% 需要它）。

## 7. 视觉规格

### 7.1 纸片底（必需）

- 纸片 = 窗口表面：`background: color-mix(in srgb, var(--paper) 94%, transparent)` + `1px solid var(--b1)` + `box-shadow: var(--shadow-float)`；直角、无圆角。
- 纸片尺寸永远等于窗口：`inset: 0`；窗口 = 内容 + 固定留白；图谱收缩/展开 → 纸片跟着变。它不是一个固定尺寸的底板。
- 深色主题自动换 `--paper` / `--b1` / `--shadow-float`；纸片随皮肤。
- 纸片的 94% 透明是唯一的「半透」；图谱卡片本身 100% 纸色，保证节点文字清晰。

### 7.2 图谱材质

- 纸色卡片、墨色文字、单一 accent；根/阅读节点 `--accent` 底 + `--accent-on` 字。
- **选中态 = 根/阅读节点同款整卡 accent**：fill/stroke `--accent`，标题 `--accent-on`，类型 `accent-on` 72%；**没有外圈/双框/纸色内芯**；hover 只把描边加到 2px，不改填充。
- 字号沿用画布：根标题 15/600、节点标题 13/500、类型/关系/时间 11、解释 12。
- 直角；零圆角；零渐变；零发光；零毛玻璃。唯一的阴影是纸片的 `--shadow-float`。
- **无 casing**：纸片底已经提供对比；边线 1.2px / 55% 墨色；关系字与时间字直接填 `--t3`。
- 不新增字体、颜色、圆角、阴影 token；`scripts/skin-audit.mjs` 必须无新增告警。

### 7.3 控制轨

- 轨高 24；标题胶囊 + 居中动作 + 右侧置顶/关闭；每枚胶囊 `--paper` 底 + 1px `--b1`；active 用 accent。
- 宽窗动作：`跳到原文` / `它在说什么` / `深挖` / `在完整图谱中打开`；窄窗（< 520px）：`原文` / `解释` / `深挖` / `全图`。
- 动作条 24px 高、11px 字；hover 才变 accent；「跳到原文」只用 accent 文字/描边，不给 accent 填充（§5.3 / D142 克制口径）。
- 标题胶囊是唯一拖动区；按钮 `no-drag`。
- 轨自动隐藏；选中节点时自动亮 2.5s；`Tab` 聚焦/上缘悬停保持。
- **没有角标**。

### 7.4 解释卡 / 状态 / 模式胶囊

- 解释卡：纸底 + 1px `--b2`；顶部从轨下 36px 起；宽度 `min(420, winW - 32)`；水平居中；max-height = 窗口高 − 52；超出滚动；无阴影。
- 卡头：`它在说什么`（11px `--t2`）+ 节点标题（10px `--t3`，截断）+ `收起`；正文 12px/1.7。
- 状态条：纸底 + 1px `--b1`；左下；4s 自动消失。
- 模式胶囊（全图）：纸底 + 1px `--b2`；左下；`全图 · 0.46×` + `回到聚焦`。
- **没有节点浮条、没有角标、没有检视框、没有锁定徽标。**

### 7.5 动效

- 控制轨淡入 120ms / 上移 2px；解释卡淡入 140ms。
- 图谱生长沿用现有 `planTransition` + 生长动画；窗口/纸片边缘**默认瞬时落位**（避免 D198 黑边），让「图的生长」承担动效。
- 若 D198 spike 证明透明窗口的 `setBounds` 无黑边，再评估 160ms ease-out 的窗口/纸片缓动；不作为首版必需。样张的 180ms 只是演示。
- `prefers-reduced-motion`：控制轨/解释卡/窗口全部瞬时；生长动画沿用现有降级。
- `--spring` 仍冻结（§5.1），不引入回弹。

### 7.6 明确不用

毛玻璃、背景模糊、发光/霓虹、渐变描边、大圆角、悬浮卡片阴影（纸片本身除外）、玻璃拟态、把 accent 当背景大面积铺、casing、角标、检视框、锁定徽标、节点浮条。

## 8. 技术契约

### 8.1 BrowserWindow

```js
new BrowserWindow({
  width: 360, height: 248,          // 种子（320×200 卡 + 留白）；首次 fit 后改
  frame: false,
  transparent: true,                // 纸片 94% + 阴影需要透明窗口
  resizable: false,                 // 原生缩放退役；尺寸由 setBounds 驱动
  hasShadow: false,
  roundedCorners: false,            // Windows 11
  backgroundColor: "#00000000",
  show: false,
  alwaysOnTop: pinned,
  webPreferences: { preload, contextIsolation: true, nodeIntegration: false, backgroundThrottling: false }
})
```

- `reveal()` 不再 `setBackgroundColor(themeBackground())`；只 `setAlwaysOnTop(pinned)` + `show()`。
- 只有显式呼出才 `focus()`；自动尺寸更新不抢焦点。
- 所有尺寸走 `setBounds(bounds, false)`；纸片 `inset: 0` 随窗口。

### 8.2 IPC

新增一条 invoke（渲染层量内容，主进程算尺寸/落位）：

```ts
type LensFitRequest = {
  content: { w: number; h: number };                 // 图谱 layout bounds（100%）
  anchor: { id: string; x: number; y: number; w: number; h: number };
  current: { scale: number; offsetX: number; offsetY: number };
  mode: "fit" | "focus" | "all";
};
type LensFitReply = {
  scale: number;
  bounds: { x: number; y: number; width: number; height: number };
  workArea: { x: number; y: number; width: number; height: number };
  clamped: boolean;
  tier: "100%" | "scaled" | "focus" | "all";
};
```

- `lens:fit`（渲染层 → 主进程，invoke）：主进程用当前窗口所在显示器的 `workArea` 算 `s`，按锚点算新原点，钳制后 `setBounds`，返回实际值。
- 渲染层负责：量 `content` / `anchor`；聚焦模式下先试 N、再发 `lens:fit`；拿到 `scale` 后按该比例绘制。
- `lens:window` 推送保持 `{ visible, pinned }`；`win:lens` 保持 `toggle / show / hide / pin`。
- **不新增 locked 字段、不做 lock/unlock、不做自动解锁。**
- 不新增设置键；纸片底是必需，没有开关。

### 8.3 渲染层

- `MindmapCanvasV2`：
  - `MindmapCanvasHandle` 增加 `getBounds()`（layout bounds）与 `getNodeRect(id)`（节点在内容坐标的矩形）。
  - 新增 `setViewScale(s)` / `autoFit` 控制：透镜窗口由宿主决定比例，画布不再用 48px 内边距自行 fit；完整图谱页签保持现状。
  - `reveal(id)` / `center(id)` 仍可用；聚焦/全图切换后由宿主调用。
- `MindmapLens`：
  - 结构从「标题 + 画布 + 底部详情」改为「纸片 + 画布 + 控制轨 + 解释卡 + 状态/模式胶囊」；底部详情与节点浮条退役。
  - 新增 `measure` 副作用：`canvas.getBounds()` → 计算 content/anchor → `window.lensAPI.fit(...)` → 按返回的 `scale` 绘制。
  - 聚焦视图：在现有 `lensGraph` 基础上做派生裁剪（保留阅读节点/祖先/选中；其余按 N 折叠；合成「另有 N 项」）；不改 `overrides` 真值。
  - 控制轨动作：选中节点后渲染四个动作到轨的中间区域；宽/窄文案切换；动作事件统一在轨上处理。
  - 空态/加载态用种子卡；保留 `needsGenerate` / `scopeStreaming` / `feed.unsupported` 文案。
  - `onStage` / 正文强调 / `anchorEpoch` 等 D199 逻辑原样保留。
- `lens.tsx`：桥接 `fit`；`onWindow` 保持 `{visible,pinned}`；`Esc` 仍隐藏；主题/语言初始化不变。
- `lensBridge.ts`：`fit` 走 invoke；`control` 保持 toggle/show/hide/pin；缓存/回执逻辑不变。
- `Reader.tsx`：工具栏按钮保持 toggle；没有「解锁结构图」；D202 的「每会话从关开始」不变。
- `theme.css`：`.lens-root` 保持透明；`.lens-window` 纸片底；旧 `.mm2-focus-head` 拖动/底部详情样式退役；新增 `.lens-rail` / `.rail-center` / `.rail-actions` / `.lens-explain` / `.lens-status` / `.lens-mode-chip`；标题胶囊 `-webkit-app-region: drag`；**不加 casing / tick / hud / lock / frame 样式**。
- 不新增 `vite` 入口；不新增 AI / DB / 调度。

### 8.4 焦点与偏好

- 聚焦只影响「透镜窗口」的显示，不写入 `overrides`、不改变用户在完整图谱里的折叠偏好。
- 「展开全部」是会话态；切换预设、切文档、重新呼出都回到「默认分级」。
- 阅读节点变化时，窗口先按新内容分级，再以阅读节点为锚点落位；不因为阅读位置变化而把窗口拖来拖去（仅内容变化时 resize）。

### 8.5 错误与兜底

- `lens:fit` 失败 / 无回应：回退固定 520×660（D197 的旧尺寸），纸片保持 94%；日志记录，不阻塞显示。
- 工作区过小（< 480×320）：用 360×160 最小窗，图内部按 0.62 渲染并允许平移；不再要求「一次看全」。
- DWM 关闭 / 透明不可用：窗口会退化为不透明黑底（Electron 硬限制）；文档写明 Windows 10/11 默认 DWM 为基线，不为此加兼容分支。
- 2s 安全阀 / 离屏守卫 / 挂起取消：D200 既有逻辑不动。
- 透明窗口 + `setBounds` 的黑边：D198 spike 结论决定是否做窗口/纸片缓动；不做则默认瞬时落位。
- 点击拦截：不做穿透；纸片是可见实体；用户通过拖动/关闭解决遮挡。

### 14.5 T5 · D198 透明窗口 `setBounds` spike 实测（2026-10-21）

- 环境：本机 Electron 31 / Windows；`transparent:true / frame:false / resizable:false / hasShadow:false / roundedCorners:false / backgroundColor:"#00000000"`；DPR 2.5。

## 15. D204 / v49.30 展开/收起的锚点与窗口缓动（2026-10-21）

> 用户原话：「现在点击节点展开更详细的分支时，窗口扩展特别生硬，像闪了一下，不够流畅丝滑。请修改为：点击节点进行展开时，该节点位置固定不动，以其为中心进行展开和扩展窗口，要保留原有的图谱展开生长动画。」

### 15.1 根因

1. **锚点算错**：`lens:fit` 的旧公式用「**新布局**的节点矩形 × **旧视图**比例 + 旧窗口原点」反推节点旧屏幕位置。展开后节点在内容坐标系里的坐标已经变化，于是窗口原点被推到错误位置，节点在展开瞬间跳一下。
2. **生长动画被截断**：内容/比例一变，渲染层的 `setViewScale` 重置视图并清空画布过渡帧（`trRef=null`、`shownRef=target`），`planTransition` 的展开生长动画刚起就被窗口 fit 的重置截断，表现为「闪一下」。
3. 窗口 `setBounds` 瞬时落位（D203 §7.5 为规避 D198 的决策），尺寸跳变本身也放大了生硬感。

### 15.2 修法（D204）

- **锚点**：`lens:fit` 请求增加 `anchorScreen: {x,y}`——点击节点中心在**旧**布局下的屏幕 DIP 位置（渲染层在改 `overrides` 之前用节点卡片 `getBoundingClientRect()` + `window.screenX/Y` 捕获）。主进程的期望原点改为：
  ```text
  desiredX = anchorScreen.x − 16 − (anchor.x + anchor.w/2) × s
  desiredY = anchorScreen.y − 32 − (anchor.y + anchor.h/2) × s
  ```
  其中 `anchor` 是**新布局**里同一节点的矩形。这样新窗口原点 + 新节点中心 × s 恰好落在旧屏幕位置；贴边钳制时照旧 `clamped=true`。
- **窗口缓动**：`lens:fit` 请求增加 `animate: boolean`。窗口可见且 `animate=true` 时，主进程从当前 bounds 到目标 bounds 做 **180ms / cubic-bezier(.2,.7,.2,1)** 的 `setBounds` 插值（16ms 步进）；隐藏时仍只暂存。新一次 fit / hide / closed 终止上一条动画（hide 先补到目标再隐藏），避免动画残留。
- **内容固定**：渲染层在 fit 回复后给图谱宿主加**同时长、同曲线的反向位移**：从 `目标原点 − 旧原点` 到 0。窗口原点从旧到目标、宿主反向位移从差值到 0，两者相加使宿主/内容在整个动画期间停在目标屏幕位置；纸片（窗口表面）绕固定内容生长。点击节点因此屏幕位置不动。
- **保留生长动画**：展开/收起触发的 fit 立即发出（不等 80ms 防抖）；同比例（scale 不变）的内容变化**不再调用 `setViewScale`**（只改宿主尺寸），画布的 `planTransition` 继续跑；透镜给画布 `viewAnchor={false}`，把锚点所有权交给窗口/宿主，避免画布视图补偿与窗口锚点互相打架。
- **D198 取舍**：缓动重新引入 D198 的透明窗口 resize 黑边风险。T5 spike 在 capturePage 下 10/10 未见新区域黑边；若真机出现黑闪，回退为瞬时落位（D204 保留 `animate` 开关，默认只对展开/收起开启）。

### 15.3 验收

- 纯几何：`anchorScreen` 输入下新窗口原点使节点中心落回旧屏幕点（非贴边 ≤1px；贴边 clamped）；旧 `bounds/current` 路径不回归。
- 主进程：`animate=true` 时 bounds 逐步逼近目标（中间值 ≠ 最终值）、~180ms 到位；`hide` 后不残留动画；D200 九项保持。
- DOM：展开/收起时 fit 请求带 `anchorScreen` + `animate:true`；宿主出现反向位移；`setViewScale` 不被同比例内容变化调用；`viewAnchor=false` 时画布过渡不被视图补偿改写。
- 真实应用：点击展开前后被点节点中心屏幕位置变化 ≤2px；窗口 bounds 在 ~180ms 内单调到目标；新分支保留 `planTransition` 生长动画（刚到达虚线/入场）；无「先跳后缩」。
