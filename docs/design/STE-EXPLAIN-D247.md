# 「简明解读」v4——ASD-STE100 式逐句解释 · 多母语输出 · 设计稿（D247 / v49.76）

> 前置：`docs/design/STE-PLAIN-DECODE-D91.md`（功能入口与 CLP 机制）、D118（节标题契约）、D148（v3 改写纪律）。
> 本稿只改 **`reader-explain-ste` 提示词契约**与**输出语言 pack 覆盖**，不改入口、不改 IPC、不改表结构。

## 0. 用户原话（2026-10-27，逐字）

> 软件当前有 AI 解释功能，支持手动选择解释方式。其中“简明解释”方式。我之前要求其他 Agent 实现以 ASD-STE 100 方式作为提示词，对用户选中文本进行解释的效果。但 ASD-STE 100 是简明技术英语，只能生成英文解释，而我的软件面向全球，因此输出结果应支持各种语言版本。
>
> 当前“简明解释”提示词的实现效果未达 ASD-STE 100 标准，未能逐句清晰解释复杂概念，仍为长篇解读。请修改提示词，确保实现 ASD-STE 100 效果，并根据软件中用户手动选择的母语，以用户母语显示解释结果。请你自行进行测试，不用在提示词测试台里面进行测试，直接使用那段提示词，然后以你自己作为模型或者使用一个子代理作为模型来进行测试，然后你来验收效果如果不符合标准则继续调整，直至符合标准

## 1. 问题诊断（对 v3 输出的实测）

v3（D148）把第 2 步定义为「简明改写」，并给出「句子上限 / 一句一义 / 逐句自查」硬规则，但实测仍有四个结构性缺陷：

1. **载体不对**：v3 要求「逐句改写」，模型输出的是对整段材料的改写稿，而不是对每个原句的逐句解释；用户看到的是「一篇改写文」，不是「逐句注释」。
2. **四节俱长**：歧义点每条要求「两三句说明」、多重解读每条一段、术语至多 5 条，全部叠加后远超原文长度，主观感受即「长篇解读」。
3. **歧义点失控**：模型把「样本量小 / 证据不足 / 研究类型」等研究方法评价也列为歧义点，甚至把普通词硬标为 `quantity-vague`，进一步拉长篇幅。
4. **多语言仅靠一句 `【解读语言】`**：模板没有输出语言总约束；`ja` 在 `resolveProfile` 中回退到 `en` 规则，`zh-Hant` 回退到 `zh-Hans` 规则；实测日文输出会残留中文标签「第 1 句」，中文输出会把日文「交絡因子」直接搬进正文。

## 2. v4 输出契约（已实测）

### 2.1 核心：逐句解释，不是改写

每个原句一组，外层与内层都用列表：

```markdown
## 逐句解释
- 第 1 句：
  - 突触修剪是发育期发生的一个过程。
  - 小胶质细胞是脑内起清理作用的一类细胞。
  - 小胶质细胞在这个过程中清除多余的神经连接。
```

- 短句数量：简单句 1 句；一般 2 句；复杂句 3-5 句；超长句可更多，但每句仍只讲一个意思。
- 每条短句必须是完整句，必须有主语和谓语。
- 禁止「本句/这句话/この文は/The sentence」式元话语开头。
- 禁止整句复述原文。

### 2.2 ASD-STE100 式硬约束（10 条）

1. 短句：中文 ≤ 30 字；英文 ≤ 18 词；日文 ≤ 30 字；其他语言 ≤ 25 词或约 40 字符（取更短者）。
2. 一句一义：分句 ≤ 2；从句嵌套 ≤ 1 层；并列同类信息可合并，不同层级的原因/条件/结论不合并。
3. 完整句：必须有主语和谓语；禁止名词短语、省略句、「……」收尾。
4. 主动语态：写明「谁做什么」；施动者不明时在同一句写「来源未说明……」；禁止为每个被动动词单独加一条解释。
5. 受控词汇：一词一义；术语首现即白话解释；不用成语、比喻、行话、文白夹杂、含糊量词；数字带单位。
6. 不增不减：原文信息点一个不丢；不加背景、评价、建议、例子；解释块里不写「原文没有给出……」。
7. 保留情态：「可能 / 提示 / 认为 / 尚不清楚 / 仍需」不得改成确定语气；直接用情态词表达，不另写一句「这只是可能」。
8. 不重复：每句提供新信息；禁止换词重说同一结论。
9. 术语保真：保留原术语并在首现处解释；不得用模糊日常词替换术语（如把「动脉粥样硬化斑块」说成「血管的硬化部分」）。
10. 逐句自查：长度、分句、语态、词汇、情态、信息完整六项逐句检查；英文逐句数词，超过 18 个拆句。

### 2.3 四节收缩

| 节 | v3 | v4 |
| --- | --- | --- |
| 歧义点 | 每条两三句说明，数量不设上限 | 至多 2 条；每条一句短句；只列**语言表达层面**障碍；禁止评审研究方法、样本量、证据强度；定义句/科普段落通常 `points=0` 并整节省略 |
| 简明改写 | 逐句改写整段 | 改名为 **逐句解释**；每个原句一组短句列表 |
| 多重解读 | 每条一段 | 仅当确实有两种以上合理读法；至多 2 条；每条一句短句 |
| 术语 | 至多 5 条 | 至多 3 条；只列专业术语；解释块已定义的不得重复 |

### 2.4 语言层

- **输出语言总约束**：模板级 `{{OUTPUT_LANG_NAME}}` 块覆盖全部输出（正文、节标题、编号标签、说明、追问回答），由渲染端按界面语言注入。
- **节标题表**：中文 / 繁體中文 / English / 日本語 四套固定写法；其他语言翻译四个标题。
- **编号标签**：中文「第 1 句」/ 英文「Sentence 1」/ 日文「第1文」；其他语言按习惯。
- **术语翻译**：材料语言 ≠ 输出语言时，原文术语必须译成输出语言标准说法；只有歧义点的「原文关键片段」可保留原文；专有名词与缩写除外。
- **ASD-STE100 名称**：模板正文允许引用标准名称（用户明确要求「以 ASD-STE 100 方式」）；仍禁止内嵌规范规则原文与批准词典词表。pack 侧维持「名称只允许出现在 `derivedFrom`」的 lint。

## 3. pack 覆盖

| pack | 状态 | 用途 |
| --- | --- | --- |
| `zh-Hans` | 既有 | 简体中文材料分析 + 输出 |
| `en` | 既有 | 英文材料分析 + 输出 |
| `universal` | 既有 | 未知语言兜底 |
| `zh-Hant` | **新增**（D247） | 繁體中文材料分析 + 输出；`zh-TW` / `zh-Hant-TW` / `zh-HK` / `zh-MO` 精确命中 |
| `ja` | **新增**（D247） | 日文材料分析 + 输出；标准术语用 ミクログリア / シナプス / プラーク / コホート研究；保留「示唆する / 可能性がある / まだ分からない」情态 |

回退链保持：精确 locale → 基础语言（zh→zh-Hans，除非含 hant/tw/hk/mo）→ en → universal。其他语言（ko/fr/de/es/ru/pt/it）仍走 en 规则包，但模板的通用句长上限（≤25 词或约 40 字符）兜底。

## 4. 实测验收（子代理充当模型，直接使用最终提示词，不经 prompt-lab）

测试方式：按 `src/lib/cards.ts` 的 ste 分支同构拼装 system/user 消息（双 pack 注入 + `{{OUTPUT_LANG_NAME}}` + 【选中文本】【材料语言】【解读语言】），把 system/user 原样交给子代理，要求它只输出 assistant 正文。共 14 类材料 × 多轮草稿迭代（v4.1→v4.9）。

| # | 材料 → 输出语言 | 验收点 | 结果 |
| --- | --- | --- | --- |
| 1 | 英文 55 词长句 → 简体中文 | 逐句解释、短句、情态、术语定义 | 通过：7-9 条短句，每条 ≤30 字；`is thought` 保留为「来源未说明谁认为」 |
| 2 | 中文 100+ 字长句 → 日文 | 日文短句、术语保真、情态 | 通过：プラーク / 微小粒子状物質 / 交絡因子 / 前向きコホート研究 均保留并解释；「示唆する」未被改成「示す」 |
| 3 | 中文 100+ 字长句 → 英文 | 英文 ≤18 词、情态 | 通过：8 条短句均 ≤18 词；`suggest / may / does not yet show` 保留 |
| 4 | 英文 55 词长句 → 繁體中文 | 繁中标题、术语、短句 | 通过：`## 歧義點` / `## 逐句解釋`；微膠細胞 / 死後間隔 保留并解释 |
| 5 | 中文 4 句段落 → 日文 | 逐句分组、points 真实 | 通过：4 组；仅 hidden-agent（「有人认为」）1 条 |
| 6 | 中文定义句 → 日文 | 简单文本 points=0 | 通过：无歧义点节；2 组短句 |
| 7 | 英文定义句 → 中文 | 简单文本 points=0 | 通过：无歧义点节；2 组短句 |
| 8 | 英文 6 句科普段 → 英文 | 不评审研究质量、不硬凑歧义 | 通过：`points=0`；6 组各 1 句 |
| 9 | 中文指代歧义句 → 中文 | multiple readings | 通过：`points=1 / readings=1`；「读法 A 指张三，读法 B 指李四；结构更支持 A」 |
| 10 | 日文材料 → 中文 | 术语翻译、不夹日文词形 | 通过：交絡因子 → 混杂因素；输出无日文词形 |
| 11 | 日文材料 → 日文 | 原生日文、情态 | 通过：ミクログリア / 交絡因子 保留；「示唆する → 示唆する」 |

| 13 | 英文长句 → 日文（分析 en / 输出 ja） | 跨语言组合、日文短句、情态 | 通过：全篇日文；`と考えられている` / `まだ不明` 保留；ミクログリア 保留并解释 |
| 14 | 繁體中文长句 → 简体中文（分析 zh-Hant / 输出 zh-Hans） | 繁→简输出、术语译成简中 | 通过：正文与节标题全简体；细颗粒物 / 炎症反应 / 混杂因素 / 前瞻性队列研究 均为简中标准说法；原文片段仅出现在歧义点引文 |

**装配回归（实测中发现并修复）**：`{{OUTPUT_LANG_NAME}}` 在 v4 模板中出现多次，`cards.ts` 原先用的 `replace` 只换首处，会把占位符漏给模型；改为 `split(...).join(...)` 全量替换，并新增 `tests/d91-cards-assembly.test.cjs`（简中/繁中/英/日四种界面语言 × 7 断言 = 28 项）锁住该缺陷与 pack 路由。

**通过判据**（人工逐条核对 + 句长目测，均满足）：语言正确；逐句分组；每句一个意思；中文/日文 ≤30 字、英文 ≤18 词；无成语/文白/比喻；术语保留并解释；情态未加强；简单文本 `points=0`；无长篇总结/建议；追问不重跑全流程。

**未覆盖**：韩/法/德/西/俄/葡/意 尚无人工 pack，依赖 en 规则包 + 通用句长上限；后续语言上线时按 D91 §6.4 的 pack 注册方式增补。
