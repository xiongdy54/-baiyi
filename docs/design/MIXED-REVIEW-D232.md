# D232：复习方式二选一——分开处理（默认）/ 混合复习（SuperMemo 式）

> v49.61。用户 2026-10-26 指令原话：「关于 C2 的"复习页合并摘录模式"，这个功能我当初设计时没想好，现在感觉有些混乱：复习页进行闪卡复习和摘录卡片处理，而摘录页也能进行摘录卡片处理，这让人迷惑。所以请你先想优化方案，让用户可以选择：1. 默认将闪卡和摘录卡片分开处理 2. SuperMemo 式将闪卡和摘录卡片混合在一起复习。如果没有较好的方案，就干脆取消这个功能，让闪卡和摘录卡片分开处理。」

## 1. 现状问题（v49.60 实测）

| # | 问题 | 根因 |
|---|---|---|
| 1 | 合并模式下在摘录上按 Z，撤销的是上一张卡的评分，摘录操作撤不掉（C2 原报告） | 复习页只接了 `cards:undoReview`（卡片撤销）；摘录页走 `undo:last`（统一撤销链），两页撤销顺序不一致 |
| 2 | 摘录条目上按空格 / 回车无反应，只能点「下一条」 | 复习页键位只为闪卡注册（翻面 / 评分），摘录分支没有键盘推进 |
| 3 | 连点「下一条」会推进两次 | 摘录分支的动作不走 `actionBusyRef` 忙碌守卫 |
| 4 | 改优先级 / 编辑正文后卡面不回写，要换条才看到 | 摘录分支回调只写库，不更新当前条 |
| 5 | 设置里只有一个「并入复习队列」开关，看不出两种用法的区别，也看不出摘录页是否还能用 | 文案按实现口径写，没有讲用户可见的差异 |

## 2. 方案比较

| 方案 | 说明 | 结论 |
|---|---|---|
| A. 取消合并模式 | 只留分开处理 | 用户的首选是「可选」，且 SuperMemo 的核心用法就是闪卡与摘录（topic）同一队列；只有在做不好时才取消 |
| B. 合并模式下隐藏摘录页 | 混合复习时顶栏「摘录」变成提示页 | 摘录页还承担浏览、批量阅读、查看态、跳原文等职能；隐藏后用户换了模式就找不到入口，反而更乱 |
| **C. 二选一 +「摘录页始终可用」+ 统一撤销**（采用） | 设置改为「复习方式」二选一；混合复习下复习页与摘录页处理同一批到期摘录，撤销同一条链 | 两种模式的差别只在「复习页里是否穿插摘录」，摘录页行为不变，心智模型最简单 |

## 3. 行为契约（v49.61）

- **设置**：「复习方式」分段控件：**分开处理**（默认）/ **混合复习（SuperMemo 式）**。存储键不变（`app.extracts.mergeIntoReview`，false / true），零迁移；「混编规则」行只在混合复习下显示。说明文案写清两种模式的差别，以及「摘录页仍可单独处理摘录」。
- **分开处理**：复习页只有闪卡，Z 只撤销卡片评分（既有 `cards:undoReview`）；摘录在顶栏「摘录」页处理。行为与 v49.60 关闭开关时逐字相同。
- **混合复习**：
  - 到期摘录按混编规则（`quota-1-4` / `by-due`，§6.8-3）穿插在复习会话里。
  - **统一撤销**：Z / 撤销按钮走 `undo:last`（与摘录页同一条链），按时间倒序依次撤销最近的评分或摘录操作。撤销评分 → 回到那张卡的背面；撤销摘录操作 → 被召回的摘录在本会话里就成为当前条。按钮标签按链尾类型显示「撤销评分（X）」或「撤销摘录操作」。键盘撤销不等 `undo:info` 的异步刷新（评分后立刻按 Z 也能撤到刚才那一下；没有可撤项时 `undo:last` 返回 ok:false，什么也不做）。
  - **键盘**：摘录条目上，不带修饰键的空格 / 回车＝下一条（读后推进）；按住不放的连发忽略；焦点在输入框、按钮、弹窗内时不拦截（同 D227 / D228 的键盘目标判定）。
  - **忙碌守卫**：推进 / 推迟 / 毕业与闪卡评分共用 `actionBusyRef`，连点只生效一次。
  - **就地回写**：改优先级 / 编辑正文后，当前卡面立刻显示新值；**不重排当前条**（与 D226 一致：改完优先级当前条不动，点下一条时按新顺序取）。
  - 顶栏「摘录」页照常可用，处理的是同一批到期摘录；两页共用同一条撤销链。
- **零写库切换**：切换复习方式不写任何调度状态（§6.8-3 既有不变量）。
