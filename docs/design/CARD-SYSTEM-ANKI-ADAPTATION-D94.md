## §1 标签系统（批 A，P0）

### 1.1 概念定位：第四条组织轴

本项目卡片已有三条组织轴，标签是第四条，四轴正交、互不替代：

| 轴 | 载体 | 语义 | 受控性 |
|---|---|---|---|
| 书（材料） | context_ref → document/library_item（JOIN 派生） | 归属：这张卡从哪本书来 | 系统给定 |
| 知识点 | `knowledge_point_id` → knowledge_points（K1/K2 归一） | 语义：这张卡考什么知识 | 半受控（提案确认制） |
| 学科领域 | `domain`（UDC 清单 ≤2，R17） | 学科分类 | 受控 |
| **标签** | `cards.tags_json` | **用户意图：用户为组织与筛选自造的词**（「考研」「口试」「错题」「待重读」） | 自由 |

判断一个功能该落在哪轴的规则：由系统从来源推出 → 书；由内容语义推出 → 知识点；由学科分类推出 → domain；**只有用户自己知道的组织意图** → 标签。

### 1.2 语法与规范化（`normalizeTag`，纯函数，渲染层实现、主进程复用）

标签 = 层级路径字符串，`父::子::孙`（Anki 语法）。

| 规则 | 内容 | 违反时 |
|---|---|---|
| 分隔符 | `::` 为层级分隔符；段内禁止出现半角冒号 `:` | 输入框即时拒绝（chip 不生成） |
| 段非空 | `a::` `::b` `a::::b` 均非法 | 即时拒绝 |
| 空白 | 整体与每段首尾空白 strip；段内空白保留（允许「错题 本」这类词） | 自动规范化 |
| 字符 | 除 `:` 与控制字符外不限制（中文/字母/数字/空格/`-`/`_`/`/` 均可） | — |
| 大小写 | **全链路大小写不敏感**：存储保留用户首次输入的写法；查询、去重、词表合并、层级匹配一律不区分大小写 | — |
| 长度 | 单标签（完整路径）≤24 字符；层级深度 ≤3 层 | CardLint **L17**（info，仅提示不阻断） |
| 数量 | 每卡 ≤8 个标签；同卡重复（大小写不敏感判定）自动去重 | L17（数量超限 info） |

`normalizeTag(raw) → {ok, tag?, reason?}` 单一实现，手动表单、批量打标、复习页打标、继承装配四处共用；`normalizeTags(arr) → {tags, lintIssues}` 供落库前统一走一遍（与 CardLint L17 同源，不另写第二份规则——制卡原则单一事实源精神，§6.3.1）。

**祖先不物化**：打 `考研::英语` 只存这一个完整路径，不额外存 `考研`。「考研」作为独立标签须用户显式另打。查询按层级边界前缀匹配补齐语义（§1.5）。

### 1.3 存储与标签词表

- **存储零 schema**：复用 `cards.tags_json`（JSON 字符串数组，空 = `'[]'`，与现状默认一致）。不建标签维表——避免第二份事实。
- **词表 = 派生缓存**（TagVocabulary）：`Map<规范路径小写, {display, cardCount, extractCount, lastUsedAt}>`。数据源 = `cards.tags_json` ∪ `extracts.tag_json`（D61 批注标签）。仅用于输入建议、快捷打标的「最近使用」、计数展示；**不是真源**，可随时全量重建。
- **失效机制**：写入口主动失效——任何成功的 `cards:setTags` / 摘录标签写入后置脏标记；读侧（`cards:listTags`）发现脏则重扫重建。进程内缓存不落盘（重启重建，本地单用户量级毫秒级）。先例：`settings.app.extracts.aiRerank` 派生缓存（§6.8-5 E1）。
- 摘录批注标签与卡片标签**词表共享、存储分列**：建议下拉把两处来源合并展示（建议项后缀标注来源「卡 12 · 批注 3」）；写入各归各列，互不同步。
- **不做全局改名**（v1；查询用层级前缀缓解），**不做跨卡自动打标**。

### 1.4 写入入口（四处，全部用户主控）

**① 手动制卡表单**（ManualCardForm，CardDock 手动态）：

- 位置：「领域标签」（UdcPicker）之后新增「标签」行，同款视觉（label + 输入 + chips）。
- 交互：文本输入，`回车` / `，` / `、` / `,` 任一确认生成 chip（中文输入习惯的逗号顿号都认）；chip 单击 × 删除；输入过程中下拉建议（词表子串/前缀匹配，≤8 项，展示完整层级路径与计数）。
- 落库：表单 tags 随 createCard 载荷走，经 `normalizeTags` + L17；主进程不做任何隐式注入。

**② 浏览器批量打标 / 去标**（CardBrowser 批量动作条）：

- 「打标签」：弹出输入（同①的输入组件），确认后对全部选中卡**并集添加**（只增不减，已有该标签的卡跳过）。
- 「去标签」：从选中卡里**存在该标签（层级前缀语义）的卡上移除**；结果 toast 如实报告：「已添加 N 张 / 跳过 M 张（已有）」。
- 事务与撤销：**单事务、无撤销日志**——实现期核对的实况修正（v3）：`batchCardOps`（挂起/恢复/推迟/删除）本就**不写 op_journal**，§6.8-7 撤销覆盖清单只含摘录批量与评分；卡片编辑域操作（含标签）与 suspend/postpone 同域＝单事务、不可 Ctrl+Z。逐条列级写 + 缺卡整批拒绝，复用卡片浏览器批量条既有机制（§6.8-6 D60、D80「单条=ids 长度 1」先例）。
- 选中行含摘录时：摘录行是否可批量打标？——**v1 只对卡片行生效**，选中集含摘录时按钮置灰并提示「标签批量仅支持闪卡行」（摘录标签走批注编辑既有入口 D61）。

**③ 复习页快捷打标**（答案揭示后）：

- 位置：卡面 meta 行（「来自《书名》」同一行）末端「＋ 标签」文字钮，**仅答案揭示后出现**（防泄题，§1.6）。
- 交互：点击展开轻输入（同建议下拉，顶部固定「最近使用的 3 个标签」一键项）；回车写入单卡（ids 长度 1 走同一 IPC）；输入框 Esc/失焦收起。
- 写入失败不阻断评分流：toast 报错，当前卡停留状态不变。
- 复习页不改任何评分时序；打标动作不写 review_logs、不进评分撤销链（属编辑域非评分域）。

**④ 批注标签继承（制卡预填）**：

- 时机：从摘录/批注发起制卡时（阅读器选中批注 → AI 制卡 / 就此制卡；摘录页卡面制卡），以 `contextRef.extractId → extracts.tag_json` 读取该摘录的批注标签，作为**标签初值**预填。
- 落点：手动表单预填 chips（可删）；AI 确认面板的卡直接携带（接受即落库，面板 v1 不加编辑位——用户事后可在卡详情/浏览器改）。
- 语义边界：继承的是**用户自己打的批注标签**（D61），非 AI 产出，不违反「AI 非事实源」；装配在渲染层完成（制卡载荷显式带 tags），主进程不加隐式继承。
- 自由制卡（无选区、CardDock「＋制卡」空表单）不预填。

### 1.5 查询语法 v2（`src/lib/cardQuery.ts`，纯函数 + 独立测试）

- 新前缀 **`tag:<路径>`**：层级边界前缀匹配——`tag:考研` 命中 `考研` 与 `考研::英语`，不命中 `考研英语`（前缀必须落在 `::` 边界或整串相等）；大小写不敏感；含空格标签用引号 `tag:"错题 本"`；负号 `-tag:` 排除。卡片行匹配 `cards.tags_json`，摘录行匹配 `extracts.tag_json`（同前缀跨两 kind 生效，与 `book:` 跨行语义一致）。
- 新前缀 **`type:<卡形式>`**：匹配 `card_type`（qa/cloze/seq/imageocclusion/application/mnemonic/formula，大小写不敏感；未知值直接按原文子串匹配 card_type，无命中即空结果，与浏览器 TYPE_LABELS 对未知类型显示原文的既有语义一致）；仅对卡片行生效，选中集含摘录时行为与 `kind:` 切换语义不冲突（不切页签，摘录行自然无命中）。
- 实现约束：cardQuery.ts 保持纯函数、可独立测试（既有测试文件扩展）；**§6.8-6 文字同步修订**——「v1 未实现 `type:` / `tag:` 前缀」清单划掉这两项（f11 文档↔代码闸门同步，其余未实现项仍不得声称已支持）。
- 浏览器搜索框的「查询语法帮助」浮层（如有）补两行说明。

### 1.6 卡面显示与防泄题

- **卡面正面永不显示标签**：标签可能含答案线索（标签「三角函数」而题面问「这是什么函数」），对齐 R6 前缀铁律的防泄题精神。标签只在两处可见：答案揭示后的 meta 行（chips，点击可快改）与卡详情。
- 复习会话顶栏显示的**范围名**（筛选牌组名）不受此限——范围是用户自选的会话级上下文，Anki 顶栏同样显示牌组名。
- 浏览器行内**不新增标签列**（v1；行内列显示随「列集与虚拟滚动」批次统一处理）；标签可见性先落两处：卡详情标签区（chips + 编辑入口 = 单卡打标/去标，ids 长度 1 走同一 IPC）+ 查询可筛。

### 1.7 CardLint L17（新规则，info 级）

| 检查 | severity |
|---|---|
| tags 数量 >8，或单标签（完整路径）>24 字符，或层级 >3 层 | info |

- 创建与编辑时跑，对 AI 卡与手动卡一视同仁（§6.3.4 纪律）；不追溯存量卡。
- L17 与 `normalizeTags` 共享同一组常量（§1.2），不写第二份阈值。

### 1.8 边界与非目标

- 不做标签维表、不做全局改名、不做 AI 自动写标签（建议制=批 F 且默认不勾选）、不做标签颜色/图标（chips 统一视觉）、不做标签统计页（G 批的按轴分组统计覆盖）。
- 摘录批注标签（D61）的既有编辑交互零改动；本设计只并入词表与 `tag:` 查询。

## §2 卡片生命周期（批 B，P0）：`cards.status` 与「不再关心」

### 2.1 列与值域

- 新列 `cards.status` TEXT NULL（`ALTER TABLE ... ADD COLUMN`，§4.1 唯一合法方式；**零回填**——NULL 视同 `active`）。
- 值域 v1：`active`（默认）| `archived`（不再关心）。UI 中文标签：正常 / 已归档。
- **不定义更多取值**：K3 探针卡退役（retired）由 §4.7 v44 契约届时扩展，本设计只预留值域空间不抢语义。

### 2.2 与既有机制的正交（三轴区分，不得混用）

| 机制 | 语义 | 入口 | 恢复方式 |
|---|---|---|---|
| `leech_json.suspended` | Leech 诊断暂停（lapses≥8 自动或手动「标记并暂停」） | 复习页/Leech 面板 | 六步向导「重置为新卡/仅恢复」（§6.3.6） |
| `cards.status='archived'` | **用户主动不再关心**：永久出队直到反悔 | 复习页/浏览器/卡详情「不再关心」 | 浏览器筛「已归档」→ 恢复；卡详情恢复 |
| `is_deleted`（软删） | 删除 | 删除动作 | 软删惯例 |

两轴正交可并存（archived 且 suspended 的卡恢复 active 时 suspended 保持，Leech 处置另行）；归档**绝不动 FSRS**：`fsrs_json` 原样保留，恢复后按原 due 继续（due 已过期则自然入到期队列），不重置、不清 due、不写任何调度日志。

### 2.3 动作与入口

**「不再关心」（归档）**：

- 复习页：答案揭示后动作区（「标记并暂停」近旁）文字钮「不再关心」。行为：归档当前卡 → **直接进下一张**（等同跳过但持久）；toast「已归档——可在卡片浏览器筛选『已归档』恢复」。不评分、不写 review_logs、不计入当日四类上限（§6.8-5 口径「处理/作答」不含归档动作）。
- 浏览器：批量动作条「归档」（复用批量机制：单事务、无撤销日志——v3 实况修正同 §1.4②；单卡=ids 长度 1）。
- 卡详情：动作区「不再关心」。

**「恢复」**：浏览器筛「已归档」后批量/单条恢复；卡详情恢复。恢复即回 `active`，队列下一轮计算自然纳入。

### 2.4 队列与统计口径（硬性）

- `computeTodayQueue` 与 `listDueCards` **两侧同步**加过滤：`AND COALESCE(status,'active') != 'archived'`——**必须排除式**（学 D58 教训：包含式会把未来未知值误排除）；f03:200「队列 ≡ listDueCards」断言继续成立。
- `SessionQueueComposer` 卡片部分恒等于 `computeTodayQueue`（§4.2-26），自动继承，零改动。
- 统计：「今日到期」若独立计数则同步加过滤；验收断言=归档 N 张后「今日到期」减 N。不做历史回溯与当日计数修正（§6.8-5 先例）。
- §4.2-20 契约描述随实现登记修订：「今日队列 = 到期 ∧ 未挂起 ∧ **未归档** ∧ 同源延后」。

### 2.5 浏览器呈现

- 查询前缀 `status:` 值域扩展：现有「新卡/学习中/复习中/已暂停」（FSRS 状态）**新增「已归档」**——用户心智一个框（卡片可见性状态），文档写明 `status:` 值域 = FSRS 状态 ∪ {已归档}。
- 默认列表**排除已归档**（视图口径，非查询语法强制——侧栏「显示已归档」开关或 `status:已归档` 显式筛选可达）；归档行降透明度显示「已归档」徽标。

## §3 本软件独有维度（批 D/E/G）

### 3.1 血缘树（卡详情「来源谱系」区，批 D）

- **数据**：复用 D87 锚点闭包（workflow 行 `contextRef.parentExtractId` 邻接表派生、防环）与 D85 聚合计数（`aggregateCardCounts`，子孙递归）。树 = 本卡所属摘录节点向上到根、向下到叶；每节点标注：引文首行截断（≤40 字）、制卡计数徽标（聚合口径）、本卡所属节点高亮。
- **交互**：节点点击 → 有锚跳原文（既有 jumpAnchor 链路，遵守 §6.8-8 阅读进度不变量）；节点「查看卡片」→ 跳浏览器锚点筛选（D87 `anchorExtractId` 既有入口）。
- **空态**：老卡 `context_ref_json` NULL → 显示「无来源锚」（与跳原文按钮同判定，不猜）。
- **约束**：纯渲染层派生（复用 D87 纯函数），零新写路径、零 IPC（数据已在 workflow 行加载面内；若详情数据面缺列则补只读读取，不建新表）。

### 3.2 生成信息区与「重新生成」（卡详情，批 D）

- **展示**（AI 卡）：generated_by、批次（gen_batch_id → ai_gen_batches：模型、时间）、提示词 scope + 版本（prompt_template_id → prompt_templates）、当时 CardLint 结果（card_issues 按 card_id）。手动卡：显示「手动创建」，无批次区。
- **「用当前提示词重新生成」**：仅 AI 卡且 `contextRef.extractId` 存在时可用；走既有 runAICards 管线（源 = 该摘录正文，当前活跃提示词版本）；产物**进确认面板走完整接受流**（CardLint + 查重），接受=**新建卡，不覆盖原卡**——原卡及其调度事实原样保留，用户自行决定是否归档原卡。理由：卡片=调度单元，覆盖改写会污染「这张卡复习了什么」的历史语义。
- **约束**：只读展示 + 复用管线；若三表读取现有 IPC 未覆盖，新增只读 `cards:genInfo {cardId}`（join 查询，零写路径）。

### 3.3 同源组可见化（卡详情，批 D）

- `sibling_key` 非空时显示「同源组」区：组内全部卡列表（卡形式 label、题面截断、FSRS 状态、due、今日是否被同源延后），本卡高亮。
- 复习页**不动**：既有「同源暂缓 N」提示（§4.16）保持原样，不加可点跳转（避免打断复习流）；解释性 UI 收在卡详情。
- 约束：只读派生；同源组语义（延后规则）零改动。

### 3.4 筛选牌组快捷条件（批 G，P2）

- **现状基线**：scope 实况为结构化条件 `{id, name, bookItemIds[], kinds[], limits}` 存 `settings.app.reviewScopes`（db.js:3339-3351、applyScope:3368-3377）。**文档漂移登记**：§6.8-5 写的 `{id,name,query,limits}` 与实况不符，属 D-DOC 类漏项，随本批契约修订一并更正。
- **结构扩展**（向后兼容，缺省 = 不限）：`{id, name, bookItemIds[], tags[], kpIds[], kinds[], limits}`，条件间 **AND**，tags 内多值 OR（任一命中，层级前缀语义同 §1.5）。
- **创建入口**：浏览器「筛选牌组」页签条件构建器——书多选 + 标签多选（词表建议）+ 知识点多选（经 KnowledgeBase 检索口径，§4.2-23；归并后的 KP 展开含 merged_into 指向）+ 类型（闪卡/摘录）。「用当前查询创建」保留：从当前查询提取 `book:` / `tag:` 条件转结构化。
- **过滤实现**：applyScope 扩展——卡片行 tags 命中 `cards.tags_json`，摘录行命中 `extracts.tag_json`，kpIds 命中 `cards.knowledge_point_id`（摘录行无 KP 字段，kp 条件下摘录行不命中——条件构建器在含 kp 条件时提示「知识点条件仅对闪卡生效」）。
- **语义不变量**：仍是「保存的范围」——不移动卡片、不改归属、共享全局预算、只能收紧上限（D58 全部维持）。

### 3.5 卡面信息密度配置（批 E，P1）

- 设置键 `app.cardFaceExtras`：`{mnemonic: true, example: true, sourceRef: true}` 三开关（f18 键登记 + §7.4 义务）。
- 作用点：复习页卡面背面的辅助字段区 + 浏览器 CardFace 预览（同一组件自动继承）；关闭即不渲染对应块。
- 不影响 CardLint（创建时质检与显示无关）；不影响卡内数据（纯显示开关）。设置页落位：复习相关设置区（具体分区名随 f18 登记定）。
