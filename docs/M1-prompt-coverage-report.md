### 4.2 设计结论（已实现为 card-literature 候选）

1. **文学/诗歌材料 = 新材料类型 `literature`**（测试台 mode 下拉「文学/诗歌背诵」），默认形式：**问答（seq 续写）**——不用挖空做骨架（R13/L8：诗歌禁逐词挖空）。
2. 候选卡型组合：续写卡（骨架）+ 开头卡组（必产）+ 措辞选择卡（核心增值）+ 原文改进卡（0-2）+ 高层次观察卡（须可对照答案）+ 名言引用双卡。
3. **与 FSRS 的相容性处理**：所有卡必须有可判定的对错（L5 明确禁止纯开放卡）；措辞卡的「主观理解」也要求具体到可对照；标点/音调不进考察点。这保证文学卡不破坏调度算法的「预览=落库」前提。
4. 归属规则沿用 R19（观点归属）：分析作者意图的答案不冒充原文事实。
5. 普通论述文（文学研究、文论）不走本模式——按 concept 路由。

### 4.4 材料类型自动识别：机制、实测与改进（v16，雨霖铃案例）

**识别方式**：`detectMaterialType`（cards.ts，主软件与测试台共用同一打包产物）是**纯本地正则/启发式规则，不调用 AI**——零延迟、零成本、可离线；路由顺序为 文学/诗歌 → 公式 → 流程 → 枚举 → 概念（兜底）。

**雨霖铃案例的根因与修复**：
1. 识别层：原规则只有公式/流程/枚举三类正则，诗词无关键词命中 → 落兜底「概念论述」。**已加 `verseSignals` 诗词启发式**：①词牌/诗体标识词（词牌、宋词、律诗、上阕…）或《词牌·题》式标题（如《雨霖铃·寒蝉凄切》）；②版式证据（≥6 短行占 80%，或单段粘贴时句号切分平均句长 ≤14 字）。识别为 literature → 路由 card-literature。
2. 解析层：首跑报「Unexpected non-whitespace character after JSON」——模型在 JSON 后附带说明文字，旧「首 { 到尾 }」切法把尾部杂质包进解析串。**extractJson 已加固为括号平衡扫描**（取第一个顶层平衡 JSON 对象，兼容前后杂质）。
3. 覆盖层：短词期望整篇背诵但续写卡未覆盖全篇。**card-literature 候选 L1 已强化为「逐句全覆盖」**：一句一卡成链覆盖首尾（首句用「开头」作上下文），禁止抽样省略；该条款优先于 G8 首轮克制（续写链一句一卡已是最小单元）。

**修复后实测（真实 GLM，v16-b 候选）**：《雨霖铃·寒蝉凄切》自动路由 card-literature；产出 9 张 seq 续写卡逐句覆盖全篇（开头→寒蝉凄切→…→更与何人说）+ 作者/名句意象/措辞赏析/结构观察等 6 张理解卡，共 15 张，25 秒完成，无解析错误。

**效果评估与改进方向**：
- **v16-c 扩展（已实现）**：①近体诗识别——≥4 行去标点后统一 5 或 7 字（唐诗/律诗/绝句，无标题也能识别，如《静夜思》27 字短诗，最短长度阈值已放宽到 20）；②现代自由诗——有《篇名》标题或诗体标识时 ≥4 短行、无标题时 ≥6 短行（行 ≤20 字占八成），且过半行带句读（排除无标点清单）、排除步骤编号；③词牌单段粘贴（短句密度）。单测样本：静夜思/枫桥夜泊/再别康桥/雨霖铃（分行+单段）均正确识别；无标点清单、步骤材料、文言+白话对照均不误判。
- 本地启发式对**文学性散文**仍不可靠（散文句式与论述文重叠，误判风险大于收益）——**手动覆盖下拉是设计内兜底路径**，散文类材料建议手动选择。
- **AI 识别的权衡**（研究结论，暂不采用）：让模型先分类需多一次完整调用，GLM 推理模型即使 low 档也有数十秒思考期，会使每次制卡延迟近乎翻倍；且分类质量收益主要落在本地规则本已难判的文学散文这一小类。替代方案已入可选池：仅当本地判定为 concept 且文本呈「弱文学信号」时，才追加一次轻量分类调用。
