# 材料知识导图——功能需求与设计委托（交给 ChatGPT 的完整背景）

> 用途：本软件「材料知识导图」功能的上一版实现因生成质量不达标已整体回滚。以下是该功能的全部需求、约束、已验证的经验与失败教训，请据此重新设计实现方案。

## 一、软件背景（技术约束）

这是一款 Electron + React 的本地渐进阅读学习软件（纯本地优先：禁 CDN/外链/远程字体，一切 AI 调用走用户自己的 Key，模型为 GLM 系、流式输出、推理模型首字前约 40 秒静默）。数据库为 sql.js（内存库+全量落盘）。书籍格式：EPUB / Word / TXT / Markdown / HTML / PDF（原生渲染）/ MOBI 等。已有能力（可复用）：内核级「按章节区间抽取原文文本」（全格式已打通）；提示词版本化播种与测试台；制卡管线（确认面板逐张确认 + CardLint 质检 + 知识点归一）；用户自有知识图谱（知识点+关系）；DOMPurify 消毒。

## 二、功能定位（最高原则，用户拍板）

1. **两图分立**：导图＝「这份材料的作者对知识的整理或组织方式」（每份材料独立产物）；知识图谱＝「用户大脑中积累的知识画像」（软件已有）。两图**独立并行、允许联结**——联结只经「从导图节点制卡 → 复习 → 产生学习证据 → 图谱长出知识点」的真实学习链路。**导图永不直接写入知识图谱、不产生掌握度证据、不参与复习调度与推荐**（「书说应该懂这些」永远不冒充「用户懂这些」）。
2. **质量优先于成本**（用户反复强调）：是否生成由用户决定，但一旦生成，**以质量为先、成本让位**——绝不允许用字数截断等方式丢原文信息；费用预估必须与实际发送一致（按实测字数计算）。
3. **入口与粒度**：阅读器工具栏目录按钮旁「导图」按钮进入；生成前选择范围（整书 / 某章 / 更小结构，按本地解析出的章节层级树选）+ 覆盖粒度（粒度越高分析越细、调用越多，选择界面显示预估调用量与 Token，费用可预期）；按需生成（不做后台自动生成）、随时回看、可重新生成。
4. **交互形态**（已实现并获认可，保留）：点击「导图」切换到**占满整个软件窗口的全屏界面**，界面中只展示生成的导图（画布占满）；生成相关操作全部收进**右侧边栏**；原按钮变为「正文」，点击返回材料正文。从导图节点可一键「就此制卡」。
5. **管线纪律「图先于图示」**：先产出结构化 JSON（层级/图结构，节点可追溯原文依据 span），经**本地校验**（编造节点拒绝 / 孤儿节点标出 / 层级断裂检查 / 依据 span 与原文逐字抽查）后才渲染图示；结构层出错只重跑结构层，图示回看零调用。生成前有「发送前预览」（将发送什么、多少次调用、多少 Token）。分片缓存：章节级抽取结果按「材料+章节锚点+提示词版本」缓存，重复生成只补缺失/失效章节。
6. **制卡联结**：导图节点「就此制卡」走既有制卡管线（逐张确认 + 质检 + 知识点归一），并可注入**有界的整书结构摘要**（解决选区制卡时 AI 缺乏整书把握的痛点）；节点上标记学习状态（已有 N 张卡 / 知识点已存在）。
7. **图示风格**（源自 diagram-design，MIT，github.com/cathrynlavery/diagram-design）：最高质量的动作通常是删除；目标密度 4/10；强调色只用于 1-2 个焦点元素（editorial 而非旗帜）；禁阴影/渐变；圆角 ≤10px；所有坐标按 4px 网格；连线防交叉（bridge/hop）；细节阶梯 ≤24/12/7 节点；自包含 SVG、无脚本、无外部字体引用（纯本地红线，覆盖原 skill 的 Google Fonts 项）。

## 三、上一版实现与失败教训（重新设计的核心输入）

上一版（已回滚，代码快照在 docs/m15-archive/）的管线是：① 本地解析章节树（目录，零调用）→ ② 逐章调 AI 做「六维难度评估 + 知识点候选提名」→ ③ 一次 AI 调用把各章产物聚合成「作者视角主干结构 JSON」→ ④ 本地校验后，再一次 AI 调用把结构 JSON 渲染成自包含 SVG。

**实测暴露的问题（这是本次重新设计要解决的核心）**：
- 聚合出的「主干结构」空洞、笼统，没有真正体现「作者组织知识的方式」；
- AI 直接生成整幅 SVG 的观感差、成功率低（长 SVG 容易截断/变形）；
- 章节抽取阶段让模型「提名知识点候选」的产物粒度不对，聚合时凑不出有洞察的层级。

**需要你设计的方向**（供参考的问题域）：
1. 怎样的抽取/聚合策略能让 AI 真正提炼出「作者视角的知识组织结构」？（例如：是否该先让模型总结每章「作者在做什么/怎么展开」而非提名知识点？聚合是逐层向上归并还是一次给全文？是否引入「目录结构作为骨架先验 + AI 只做归并和命名」？）
2. 图示渲染怎么做既保证质量又稳定？（本地确定性布局（输入结构 JSON → 确定性生成树形/思维导图 SVG，零 AI、永不失败）vs AI 生成 SVG vs 混合：AI 只决定布局类型与焦点，几何由本地计算。）
3. 章节多的大书如何平衡？（层级归并？分批聚合？总览+细部两层导图？）
4. 提示词如何写才能稳定输出符合校验器约束的结构 JSON？

## 四、硬性边界（不可违反）

- 纯本地：禁 CDN/外链/远程资源；AI 调用仅走用户自己的 Key；
- 生成 = 用户主动触发 + 发送前预览 + 无 Key 时可读降级（不静默失败）；
- 导图不写知识图谱/掌握度/复习调度/推荐；不做自动生成；不做逐条确认流；
- 产物与结构 JSON 入库并随备份；节点的原文依据必须逐字来自材料（本地可校验）；
- 每次实现前先把方案写入项目开发指导文档再动代码。
