## 0. 一句话

> 当前成本 = **可展开节点数 × 单次调用成本**，与材料字数几乎无关。因此优化顺序是：**减少无效/重复任务 → 批量合并 → 精简单次输出职责 → 才轮到并发**。

### 1.3 两处口径修正（对上一轮评审的回复）

1. **「evidence coverage 57.1%」不是结构覆盖率**。57.1% 是**证据引文并集**（每条引文仅 5–30 字，天然稀疏）；应用里 `computeMapMetrics.evidenceCoverage=100%` 是**节点级**有证据比例——两者都不是「多少原文进入了结构」。
   **真正的结构覆盖率 = ⋃(节点自证据推导的 ownedSpans) / coverageUniverse = 68.1%**（叶 65.6%）。注意：**不能**用「⋃全部节点 sourceSpans」——根节点的 `sourceSpans` 是分析播种范围（= 全文），那样算会恒为 100%（详见 §3.1 三概念拆分）。D3 的问题依然成立（858 字无归属），但基数是 31.9% 而不是 43%。
2. **`completeness=complete` 不是「状态写错」，而是「没有这个口径」**。当前 `complete` 只表示「预算没触顶 + 校验通过 + 评审未 fail」，从未基于覆盖率判定。修法 = **新增结构覆盖率口径并接入 completeness**（见 §3.4），不是改一个错数字。
3. **「单靠字数不能判原子性」已被数据证明**：零产出 52–77 字，有产出 69–439 字——**区间重叠**。阈值 80 字可完整捕获 7 次零产出，但会误杀 1 次（`#12` 69 字→2 子）。→ 原子判定必须是**多特征 + 高置信才跳过**（§4.3）。

## 2. 第二部分：三种 Expand 架构（A/B/C）与设计细节

### 2.1 架构定义

| 架构 | 定义 | 预期收益 | 预期风险 |
|---|---|---|---|
| **A（现状基线）** | 1 请求 = 1 节点 × 单层 | — | 24 请求 |
| **B（批量单层）** | 1 请求 = N 个节点 × 各自单层（每节点独立输出块） | 请求数 ÷ N；固定成本（指令/推理启动）摊薄 | 输出量叠加可能溢出；单节点失败牵连整批（需隔离） |
| **C（有界递归 2 层）** | 1 请求 = 1 节点 × 最多 2 层子树 | 请求数 ≈ ÷2 | 输出暴涨；越界风险（子结构超出该节点作用域） |

### 2.2 架构 B 的可行性：系统提示词已经定义了批量输出契约

`MATERIAL_MAP_SECTION_PROMPT` 现有契约（v3，现行）：

> 若输入含**多个**【结构路径】块（它们共享同一份原文，属同组单元），输出 `{ "nodes": [按路径顺序每路径一个下述分析对象] }`。

即**多块输入 → 多节点输出**的 JSON 形状**已经存在**并在 section 组调用中使用。深挖批量只需把它扩展为「多块 ≠ 共享同一原文，而是各自一段（可能不相邻）片段」，其余沿用：

- **每节点独立块**：`【深挖·节点 i】` + 该节点 `【原文片段 1/M】`；要求逐块输出 `{nodes:[...]}`，**块与输出按序对应**。
- **每节点独立上限**：`maxChildrenPerNode`（沿用 8）+ **每节点输出预算** `maxOutputTokensPerNode`（初值 `MAX_OUTPUT_TOKENS / N × 1.5`，即单节点可略微超用但不能独占整批）+ 整批上限 `maxNodesPerBatch = 8×N`，并受 `MAX_OUTPUT_TOKENS` 约束。
- **失败隔离必须覆盖「单节点输出爆炸」**（rev.2）：一个成员写太长导致整批 `finish_reason=length` 时，**不能让整批一起失效**。为此：
  1. **逐块可恢复解析**：批响应若整体 JSON 解析失败（截断），用「括号平衡前缀扫描」把数组中**已完整的对象**逐个救出（复用 `parseJsonLoose` 的平衡算法，改成可增量取出多个完整对象）；救出的块正常采用。
  2. **未救出的块 → 单节点回退**（每块一次独立调用，各自受 `maxNodesPerNode`/`MAX_OUTPUT_TOKENS` 约束）。
  3. 回退调用计入账本（`fallbackFromBatch: true`），并在 `metrics.batchFallbacks` 留痕。
- **必测用例（批量失败隔离，rev.3）**：构造 `A 正常 / B 超长（触发 length 截断）/ C 正常 / D 正常` 的批响应，断言最终是 **A、C、D 被正常采用 + 仅 B 单节点回退**，而**不是**整批四次重新请求——否则「合批省下的请求」会被 fallback 全部吃回去（`metrics.batchFallbacks` 必须为 1，不是 4）。
- **每节点独立证据与作用域**：每块 children 的 evidence 仍**只在该节点自己的 span 内**匹配，并继续走 `attachScopeChildren` 的钳制 + 去重（现有能力，无需改动语义）。
- **批成员确定性**：按 `(span.start, span.end, title标题排序)` 排序后组批，保证同一输入产生同一批（缓存键稳定）。
- **缓存键**：`gap:b<batchId>`，其 `textHash` 覆盖**全批成员**的 (spanHash, title, depth) 序列 → 批成员变化即失效（可接受，需在 preview 中如实反映）。
- **失败恢复（必须）**：若返回的 `nodes` 数量与批成员数不符、或某块为空/解析失败 → 该块**回退为单节点调用**（逐块补齐），其余块照常采用；整批解析失败 → 全部回退单节点。**绝不因为合批而丢节点**。

### 2.3 架构 C 的边界

- 递归深度上限 `min(2, MAX_EXPAND_DEPTH − depth)`；**输出节点数上限按层衰减**（第 1 层 ≤8，第 2 层合计 ≤25）。
- **作用域越界防护**：子结构 span 仍钳制在**该节点的 span** 内（现有 `deriveChildSpans` 逻辑直接复用，不需要新机制）——所以 C 不会重新引入 v48.11 修掉的泄漏。
- C 的产出仍需 `expandable` 标记：第 2 层若仍可展开，**入队继续**（与 A 一致）。

### 2.4 与既有机制的关系（不重复造）

- 批处理**不改变** `sourceSpans` 语义、不改 `unitAnchors`、不改 merge/global/editorial/review 四阶段。
- 批处理复用现有 `attachScopeChildren`（逐节点钳制 + 去重）、`spanJobsFor`（只切不删）、`budgetLeft()`（run 级预算）、失败隔离（单作业失败 → `partial:call_failed`）。

## 3. 第三部分：Coverage 修复（结构覆盖率进审计）

### 3.1 口径（新增，唯一权威）——三个概念必须分清

**rev.2 关键修订**：`sourceSpans` 是「节点**拥有/解释**的文本」，与「本次要分析的范围」不是同一件事。必须分开：

```
Material（材料全文）
  └── coverageUniverse = 本次应被结构分析覆盖的完整范围（book scope = [0, materialLen]）
        │
        └── analysisScope(root) = 首层调用实际阅读的范围（= coverageUniverse；分片时 = 该组覆盖区间）
              │
              └── sourceSpans(node) = 节点自证据推导出的「拥有」范围（**不含**播种的分析范围）
```

**为什么必须拆**（否则指标自欺）：

- 代码现状：根节点 `sourceSpans` 被播种为 `[[0, materialLen]]`（`assembleTocLayer`）。
  → 若按「⋃全部节点 sourceSpans / 材料长度」算，**覆盖率恒为 100%**，指标彻底失去意义。
- 反之若拿「根节点自证据推导的 span」当审计宇宙，又会小到失真的程度（本例根本节点证据跨度仅 81 字，而它实际分析了整篇 2,688 字）。
- 两条路都错 → 必须显式区分三者。

**权威定义（rev.3：三个文本级指标各有独立含义，禁止互相替代）**

```
# 文本级（新增；口径 = 区间并集 / coverageUniverse）
evidenceTextCoverage  = |⋃(exact evidence 命中区间)| / |coverageUniverse|   ← 原文**被逐字引用**的比例
structureCoverage     = |⋃ ownedSpans(结构节点)| / |coverageUniverse|        ← 原文**被结构节点归属/解释**的比例
structuralResidual    = coverageUniverse − ⋃ ownedSpans                      ← **尚未被任何结构节点解释**的文本
leafCoverage          = |⋃ ownedSpans(叶节点)| / |coverageUniverse|
residual(node)        = ownedSpans(node) − ⋃ ownedSpans(children)
residual(root)        = coverageUniverse − ⋃ ownedSpans(已分析的一级节点)     ← 根级审计面（≠ ownedSpans(root)）
```

**命名纪律（rev.3，避免破坏既有语义）**：`computeMapMetrics.evidenceCoverage` **已存在且含义不同**——它是**节点级**「有证据的节点占比」（`withEvidence / nodeCount`，core 测试断言 2/3 = 0.67）。因此：

- **保留** `evidenceCoverage` = 节点级（不改名、不改语义、测试不动）；
- **新增** `evidenceTextCoverage` = 文本级逐字引用比例（上文公式）；
- 三者在 UI/profile 输出中必须**分别标注中文名**：证据节点覆盖率 / 证据文本覆盖率 / 结构覆盖率，**禁止用其中任一替代另外两个**。

> 本文基线数字对应关系：`evidenceTextCoverage = 57.1%`、`structureCoverage = 68.1%`（叶 65.6%）、`structuralResidual = 858 字（31.9%）`。

### 3.1b 区间集合纪律与守护测试（rev.3）

**规则**：一切 span 运算（union / intersection / difference / overlap / coverage / residual）**必须**走真正的区间集合算法、**支持多个不连续区间**；**严禁**用 `min(start) ~ max(end)` 的包络替代——那会把中间未归属的文本错误算成已覆盖。

**现状核对（已在代码确认，无需改造，只需守护）**：`electron/mindmapCore.js` 的 `normalizeSpans / intersectSpans / subtractSpans / spanLengthOf / residualSpans / deriveSourceSpans` 全部是区间集合运算（逐区间钳制用 `Math.min/max` 属正确用法，不是包络近似）；引擎侧 `unitAnchorsOfSpans`（逐 span 求交）、`attachScopeChildren`（逐 span 键去重）、`spanJobsFor`（逐区间切片）同样基于区间集合。
**唯一例外**：诊断脚本曾用「证据偏移包络（min–max）」做**报表展示**——那是展示口径，**不得**进入任何判定逻辑。

**必测用例（写入 core 测试）**：

```
① 非连续不得视为连续：spanLengthOf(normalizeSpans([[100,150],[900,980]])) === 130（≠ 880）
② 残余正确跨空洞：subtractSpans([[100,980]], [[100,150],[900,980]]) === [[150,900]]
③ 覆盖判定不吞空洞：⋃ownedSpans 含空洞时，structureCoverage = 各段之和 / universe，不得等于包络比
④ 多区间父节点的子 span 钳制：父 [[100,150],[900,980]] → 子不得落在 [150,900) 中间被误纳
⑤ 深挖 payload 只含所给片段（已有 E16 断言，保持）
```

### 3.2 审计对象必须包含 root（根不 expand，但必须审计）

**审计面用 `residual(root) = coverageUniverse − ⋃ ownedSpans(一级已分析节点)`**，而不是根自身的 span。

对**每个**已分析节点（含 scope root）计算 residual，并把每一段残余**分类**：

| 分类 | 判定 | 处置 |
|---|---|---|
| `transition` | 残余段 < `TRANSITION_MAX_CHARS`（初值 120）**且**不含结构线索（见下） | 记为过渡文本，不建节点 |
| `structural` | 残余段 ≥ 阈值，或含结构线索（分点/列举标记「第一/其次/另一方面/：」、多个句末符、序号） | 生成 **gap-fill 作业**（只读该残余段，沿用现有 gapfill 通道与预算） |
| `budget_deferred` | 预算不足 | 记 `partial:coverage_gap`（不伪装 complete） |

- **root 的 residual 必须审计**：本文的 root（n1，8 个一级子节点）从未入队，导致「整篇 − 一级结构」这一层从未核算 → 858 字缺口无人发现。修复后 `coverageGapCount` 不得再是 0 假象。
- gap-fill 与 expand 共用同一套预算与调用日志；除 `GAP_FILL_MAX_ROUNDS`（2）外，**新增不变检测**：
  ```
  若 (本次 gap 任务的输入 span hash == 上次) 且 (产出的子 span 并集 hash == 上次)
     → 立即终止该区段的补漏（记 gap_fill_stalled），不再发起第 N 轮
  ```
  该检测比纯轮次上限更健壮（轮次上限只在「跑满 N 轮」时止损，不变检测在「原地打转」时立即止损）。
- 目标**不是**把覆盖率机械推到 100%：过渡/修辞/重复文本就该记为 `transition`；目标是**能回答「这 858 字为什么不在结构里」**。

### 3.3 覆盖账与 completeness 的关系（诚实状态）

```
completeness = complete      仅当：预算未触顶 ∧ 无未处置 structural residual ∧ 评审未 fail
             = partial:coverage_gap   当存在 structural residual 未处置
             = partial:call_budget    预算触顶
             = partial:call_failed    单作业失败隔离后
```
UI 文案（沿用 v48.11 的诚实口径）：「导图已生成，仍有 N 段原文尚未进入结构（约 X 字）」+ 一键「继续补全」。

### 3.4 期望收益（provisional，待 benchmark）

## 4. 减少无效与重复调用（第一层优化）

### 4.1 同 span 兄弟：**上游修法优先，碰撞合批兜底**（rev.2：原「只保留一个任务」已撤销）

> **为什么撤销**：相同 span ≠ 相同语义（同一段原文既可能承载「作者提出的因果关系」，也可能承载「作者对该关系的限制」）。静默跳过 = 为性能丢结构，与「质量优先于成本」冲突。本文的 `x70/x71/x72`（span 全等 `[[580,625]]`，45 字）**在语义上可能确实是三个并列的独立标签**（考研失败 / 水硕 / 县里上班），**尚未证实**——它应当作为 benchmark 的 collision fixture，而不是当作「去重正确」的证据。

**修法 1（上游，首选）：要求子节点 span 细分到各自片段。**
根因是上游那次调用把**一句话**拆成 3 个节点，却让三者都继承了同一整段 span。因此：

- 提示词侧要求：把一句话/一个列举拆成多个并列项时，每个子节点的 `evidence` 必须落在**各自那一小段**上（而非整句）；
- 本地校验：同一父节点下若多个兄弟的 `ownedSpans` **重叠率 > 60%**，打 `siblingSpanOverlap` 警告；本地可**自动细分子 span**（按各自 evidence 的命中区间重新推导，不合并节点）——这一步零成本，且能把「同 span 碰撞」从源头消掉。
- 只有细分后仍完全相同时，才进入修法 2。

**修法 2（兜底）：碰撞节点合批，不得静默丢弃。**

```
同一父节点下 ownedSpans 完全相同的兄弟 → 组成 collision group
        ↓
1 个 batch 请求（每个成员独立块：标题 + 父链 + 各自片段 + 各自 maxChildren）
        ↓
输出 { nodes: [ {nodeId: A, children: [...]}, {nodeId: B, ...}, {nodeId: C, ...} ] }
        ↓
逐成员采用；确实同构的交给后续 semantic dedupe / editorial 合并
```

成本与「只跑一个」几乎相同（1 次请求），但**不丢结构**。仅当碰撞组 ≥3 **且** 合计 span ≥ `COLLISION_ADJUDICATE_MIN`（初值 200 字）时，才额外允许 1 次「是否同一结构」的裁决调用；低于阈值一律只合批、不裁决。

**唯一保留的确定性自动合并**：`ownedSpans` 相同 **且 标题经去标点后完全相同** → 真重复，合并为一（保留首个），记 `dedupeHits`。

### 4.2 小 span 合并入批（**架构 B 的自然收益**）

本文 24 次调用中 13 次实读 <100 字。批大小 N=4 时，这些小节点自动与其他节点合并，固定成本（指令 296–332 字 + 推理启动 + 约 3 s）**摊薄到 1/N**。

### 4.3 原子性判定收紧（高置信才跳过，绝不误杀）

- **可用的确定性信号**（本地可算，零成本）：span 字数、句末符数量、列举标记、是否含「：」引导、是否单句、相邻证据条数。
- **纪律**：只在**多特征同时指向原子**时才跳过（例如 `spanChars < 80 ∧ 单句 ∧ 无列举标记`），否则一律走 AI。原因是实测两类分布**重叠**（零产出 52–77 字 vs 有产出 69–439 字），单特征阈值会误杀。
- **提示词侧**：`expandable` 的判定标准需要在 v3 提示词基础上**收紧措辞**（当前表述「仍存在尚未被 children 表达的、具有独立作者组织意义的结构」被模型过度乐观使用）。收紧后需用 benchmark 验证 D1 比例（29%）是否下降。
- **产出契约精简（变体，需实测）**：让 expand 只输出 `{title, authorialRole, relationToParent, evidence, expandable, stopReason}` + `children`，把 `progression/centralQuestion/mainMove/relationToSiblings/groupingBasis` 留给 merge/editorial。
  **风险已标注**：merge 阶段的输入依赖子节点的 `progression`（`finalizeUser` 取 `progression`），精简会改变 merge 质量 → **必须作为 benchmark 变体测，不得直接采用**。

## 8. 风险与不做的事

| 风险 | 缓解 |
|---|---|
| 合批导致输出溢出/JSON 失败率上升 | 每批 ≤6，`MAX_OUTPUT_TOKENS` 硬约束，失败**逐块回退单节点**（不丢节点） |
| 去重误合并两个真实独立结构 | **唯一权威规则（rev.3 统一）**：`同 canonical span 且去标点后标题完全相同` → 才允许本地零成本确定性合并；`标题不同` → **碰撞组 → 合批分析 → 每个节点独立获得各自 children → 绝不静默丢节点**（详见 §4.1，风险表不再保留任何旧表述）。`siblingSpanOverlap`（>60%）**只是诊断/质量信号，不是拒绝或删除条件**——同一段原文被「核心观点」与「对该观点的限制」共同依赖是完全合法的 |
| 原子性启发式误杀 | 只在多特征高置信时跳过；benchmark 必须报「被跳过的节点若走 AI 原本会产出多少」（用 E1 的对照跑实测） |
| 输出契约精简损伤 merge 质量 | 列为变体单独测；`progression` 等字段默认保留 |
| root 补漏把成本推向失控 | gap-fill 与 expand 共用 run 预算；`GAP_FILL_MAX_ROUNDS=2`；超出记 `partial:coverage_gap` |

**本轮明确不做**：不改 `sourceSpans` 语义、不改四个归并阶段、不改渲染/布局、不引入新依赖、不调 `recursiveDepth` 默认值（等 benchmark）。

### P0 抓出的真 bug（由 §3.1b 守护用例实测发现，已修）

`core.deriveSourceSpans` 原为「**先扩边、后钳制**」，于是**落在父作用域之外的 evidence** 会在扩边阶段长进父区间、再被钳制成父的整段——把本应判为 `scopeConflict` 的情况伪造成合法归属；极端情况下一个子节点可以「拥有」整篇材料（等价于 v48.11 修掉的泄漏在边界条件下的残留）。修法：**先按父范围裁剪候选簇，再逐簇扩边，且扩边被限定在「包含该簇的宿主父区间」内**。守护用例 ④/④b 锁定（core 79/79）。

## 12. 用户实测修复（v48.12-fix1，2026-09-19）

用户在 2,688 字文章上复跑（20:08 那笔）后报了两个问题，均已定位为**确定性缺陷**并修复：

### Fix-1 删除的版本「复活」——根因不是删除，是**每次生成落两行版本**

- **现象**：删掉某一版导图后，生成新版时旧版又出现在「历史版本」里（且标题相同、看着就是被删那一版）。
- **根因**：`finalizeMap` 每个 `generate()` 调用都会 `saveMaterialMap`（**INSERT 新 UUID**）。而 v48.11 起的阶段化让**一次用户生成 = 两次 `generate()`**（首层 `section_ready` + 续跑深挖完成），于是**每次生成都在 `material_maps` 留下两行同标题版本**；再加上删除后 `material_map_shards` 作为缓存保留，重新生成的内容与被删版本逐字相同 → 看起来就是「复活」。
- **修复**：`db.updateMaterialMap(id, patch)`（就地更新，版本身份/id 不变）+ `finalizeMap` 在续跑阶段**复用本 run 早先落下的 `run.output.mapId`**；若该行已被用户删除（`getMaterialMap` 返回 null）则照常 INSERT 新行（尊重用户的删除意图）。
- **副产品**：版本 id 全程稳定 → 「就此制卡」写入的 `context_ref_json.mindmapNodeId` 溯源链不再悬空。
- **用例**：engine **E22**（7 条）：阶段一后 = 1 行；阶段二后仍 = 1 行；id 前后一致；删除后为空；删除后重生成只出现 1 个新 id。

### Fix-2 「就此制卡」发送的是**章节原文**而非结构语义包

- **现象**：选中节点点「就此制卡」，发给 AI 的是文章全文。
- **根因**：`MindmapWorkspace.makeCards` 用 `collect.textByUnit` 拼出 ≤2,400 字**章节原文**当 `section`，`focus` 用整图 `summaryText`；而 `card-structure` 提示词的【输入块】契约明确要求 `【结构语义包】`（本节点/父链/直接子结构/证据引文），并且提示词开头写着「你拿不到原文全文——这是刻意设计」。仓库里**根本没有构建该语义包的代码**，v48.5 批C 只落到了提示词与 prop 注释。
- **修复**：新增 `buildStructureCardPackage(node, structure, maxChars=1200)`（`src/lib/mindmap.ts`，纯函数）：输出 `【结构语义包】` JSON（本节点 7 字段 / 父链由远及近 / 直接子结构 / 证据引文 / 材料级结构摘要），**超长优先砍摘要与证据条数，绝不回退去塞原文**；`makeCards` 改用它，`focus` 改为「结构卡：<节点标题>」。
- **用例**：`tests/m15r.cardpkg.test.cjs`（**12 条**，esbuild 现场打包 renderer 纯函数）：契约五字段齐全、父链顺序、**逐字不含原文句子（红线）**、≤1200 字、超长裁剪不丢核心字段、叶子节点可用。

### 顺带：新增「强制重算」开关（为前后对比 / benchmark）

预览卡新增复选框 **强制重算（忽略缓存与分片复用）** → `params.force`。原因：20:08 那笔 5 次新请求里 **26 次是缓存命中**（复用了 15:26 那笔的 24 条深挖分片），所以 3 倍提速里缓存占大头，**不能当作算法对比**。做 E1–E7 与前后对比时必须勾选它，否则测的是缓存不是算法。
