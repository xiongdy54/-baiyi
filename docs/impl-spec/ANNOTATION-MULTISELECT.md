## §1 数据模型

### 1.1 批注字段落在摘录上（R7＝1:1，零迁移优先）

`extracts` 表新增列（ALTER，随 TARGET_VERSION 递增）：

| 列 | 类型 | 用途 |
|---|---|---|
| `comment` | TEXT | 用户输入的批注文字（R8；对应 Zotero `annotationComment`） |
| `annotation_type` | TEXT | `highlight` / `underline`（v1 只这两种） |
| `annotation_color` | TEXT | 8 色板之一（R6-1） |
| `tag_json` | TEXT | 批注标签数组（R6-2） |
| `quote_range_json` | TEXT | **本卡正文里的高亮范围** `{start, end}` + 端点归属标记（R9–R12） |

`context_ref_json`（已是 TEXT JSON）内新增：`sourceAnchor{documentId,pageIndex,rects[],cfi,chapterIndex,anchorRatio,readerEngineVersion,capturedAt}`、`parentExtractId`、`rootExtractId`。

> **v2 去掉** v1 里的 `annotated_text` 快照列：范围锚（§2）已取代"子序列校验"，不再需要把批注原文拍成不可变副本。

### 1.2 跳转语义（R11/R13；R2/R4 的撤回在此生效）

| 谁 | 「跳转原文」去哪 | 落点 |
|---|---|---|
| 根摘录（从原文建） | 阅读器 · 源文档 | `sourceAnchor`（PDF：多组 rects；EPUB：cfi），原文里高亮该批注 |
| 子摘录（复习中从父建） | **父摘录卡片** | 父卡正文里的 `quoteRange`，那段高亮**居中显示** |
| 子子摘录 | 它的父（即子摘录卡片） | 同上，逐级 |
| 面包屑「原文 › 第1层 › 第2层 › 当前」 | 点任一层＝切到该层卡片 | **同样把该层的高亮范围居中**（R13） |

- 面包屑命名取该层摘录首 8–12 字，深度超 4 级折叠为 `…N 级`；当前层不可点。
- 根摘录的源锚**创建时写入后不再重算**；子摘录的锚是**父卡文本里的范围**，随父卡编辑而重映射（§2.2）——这正是 R12 要的性质：父卡怎么改，"锚"都还在。

### 1.3 多段不相邻选择 ＝ 一条批注多组 rects（R5）

Zotero 的 `rects[]` 本就是多矩形，故**不需要新实体**：一次多段选择产出一条批注，
`sourceAnchor.rects` 带多组矩形，`content_markdown` 为各段按顺序拼接（段间 `\n`），
正文里的高亮则以**多段 `quoteRange`**表示（同一条批注可有多个区间）。跳原文时多组矩形**全部高亮**。

## §2 范围锚与格式继承（本方案的核心，R9–R12）

### 2.1 什么是锚

> **锚点是"一段被标记的范围"，不是"一段文字"。** 卡内文本怎么改，范围都还在。

`quoteRange = {start, end}`（字符偏移，相对 `content_markdown`）。一条摘录可有多个区间（多段选择）。
根摘录另有原文侧几何锚（rects/cfi）用于"跳回原文并高亮"。

### 2.2 编辑重映射（R10 的机械实现）

编辑落库时，用前后文本求差量，按**标准区间变换**更新每个区间（`p`＝插入/删除起点，`n`/`d`＝长度）：

| 编辑 | 区间变换 |
|---|---|
| 插入，`p < start` | `start += n`；`end += n`（整体右移，**不继承**） |
| 插入，**`start <= p <= end`** | **`end += n`（含两端一律继承）** |
| 插入，`p > end` | 不动（不继承） |
| 删除 `[p, p+d)` 全在区间前 | `start -= d`；`end -= d` |
| 删除与区间相交 | 按交集裁掉两端并 clamp |
| 区间被删空 | 该区间作废；若一条摘录的全部区间作废 → 摘录降级为「无锚点」并在 UI 显式标记（不再谎称有锚） |

**端点归属已由用户 2026-09-25 拍死：区间起点处插入也继承**（即 `start <= p <= end` 全部继承，`p < start` 或 `p > end` 不继承）。
原 v2 里"起始不继承"的暂定值已作废。

### 2.3 原「裁定 A」作废

v1 让用户三选一的"编辑越出批注原文怎么办"（拒绝/收缩/脱钩）**在 v2 不再存在**：
范围模型把它吸收了——没有"越界"这回事，只有"区间随编辑伸缩"。这是 R12 顺带带来的简化。

### 2.4 渲染

用 **CSS Custom Highlight API**（`CSS.highlights` + `Range`）画高亮：**不碰 DOM、不污染 markdown、不与
`EditableText` 的"React 不接管子节点"契约冲突**。导出/复制时可选把范围写成 `==…==`。

## §3 多段选择交互（R5）

- **键位**：默认 `Ctrl`（macOS `Cmd`），可配置 → `settings.app.multiSelectKey`（§7.4 登记 + f18 用例）。
- **行为**：已有选区时，按住修饰键再拖选/双击 → 追加一段；重复切换同一段＝移除；`Esc` 清空全部。
- **高亮**：与 §2.4 同一套 Custom Highlight（`CSS.highlights.set('multi-select', …)`）。
- **载荷**：动作层（制卡/AI 制卡/AI 解释/摘录/查词）统一收 `{spans:[{text,rects,cfi}], joinedText}`；
  制卡 `quote`＝各段按 `\n` 拼接；摘录 `contentMarkdown` 同规则、`rects` 合并多组。
- **冲突**：现有 `Ctrl+Z/X/S/A/D` 是纯键盘组合，与"按住 Ctrl 再选字"不冲突；
  但需实测 Ctrl+拖拽是否被文本层手势吃掉（**待验证项**，见 §9）。

## §4 文中留痕

| 引擎 | 做法 |
|---|---|
| PDF | 文本层之上矩形覆盖层：`--accent-soft` 底 + 左缘 2px accent 条（复用 `.card-marked` 表面规则）；有 `comment` 时加角标；hover 浮层＝原文 + 批注 + 已制卡数 + 「就此制卡」 |
| EPUB | 优先 `CSS.highlights`（cfi → Range）；退路才是自建 overlayer（**本仓零现成实现**，grep 已确认） |

契约：文中标记**只读**（点它＝跳转/浮层），编辑永远在卡片上进行。

## §5 图片：粘贴进所有编辑器

- 统一 paste：`clipboardData.items` 取 `image/*` → dataURL → `ensureImageAsset()`（**已存在**）→ 插入。
- 落点：① 卡片内联编辑框；② 批注输入框；③ 制卡输入框（`ManualCardEditor`）。
- **结构性改动（必须做）**：`EditableText` 现为"React 不描述子节点"的裸壳、落库读 `innerText`，
  而 `innerText` **丢弃图片节点** → 改为结构化序列化（DOM → markdown，图片写 `![](asset://…)`），
  同时保留"React 不接管子节点"的契约（§5.4 明写其为躲 `removeChild` 崩溃）。
- **聚焦制卡入口调整**：点**任意**图片（正文原图 / 粘贴进来的）都进聚焦层；编辑器内给 `img` 挂事件委托。

## §7 描边（R14：**搁置**）

不选型、不改行为。仅保留接口：`--field-line`（默认 `transparent`）登记为 **§5.5 皮肤扩展点**
（与 `--shadow-panel`/`--radius-pill` 同规：零消费者、皮肤可整套替换）。
样张 `design-samples/fixed-dock-both-pages.html` 的三种机制开关保留，随时可回来看读数：
环形 `box-shadow: inset 0 0 0 1px` 实测**零布局影响**（宽 720→720、行数 2→2）；边框 `1px solid` 实测 720→718。
两条硬约束已写进样张注释：**不能用 `outline`**（与 `:focus-visible` 焦点环同属性，实测会被挤掉，违反"不得移除焦点环"）；
`--field-line` 的显形值必须声明在 `body` 上（`--border-subtle` 在 `body.theme-dark` 被改写，§5.1 求值层纪律）。

## §9 未决与风险

1. **待确认（唯一边界细节）**：高亮区间端点归属——默认「起始插入不继承、末尾插入继承」；若你要「起始也继承」，改一行。
2. **风险**：偏移重映射是本方案的承重墙。任意编辑都要能正确求差量并变换区间；须以表驱动测试逐行锁死，且**多段（多区间）场景**要单独覆盖。
3. **风险**：`EditableText` 序列化改造是唯一动到既有稳定契约的改动，必须配回归（§5.4 明写其为躲崩溃而设）。
4. **风险**：EPUB 侧 highlights 需从 cfi 解析 Range，foliate 适配层无现成实现（已确认零命中），估工最大。
5. **待验证**：Ctrl+拖拽在 Electron 文本层是否被手势吃掉（决定 §3 是否换 Alt 或自定义键）。
6. **不借鉴**（Zotero 第 6 条）：同步/冲突模型、Find Available PDF（依赖其网络服务，与单机定位冲突）。
