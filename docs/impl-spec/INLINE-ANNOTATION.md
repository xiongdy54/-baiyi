## §1 数据与语义（零 schema 变更）

### 1.1 批注＝带 `comment` 的摘录（R7 1:1，不建新表）

批注文字**只存 `extracts.comment` 一处**。由此：

- 「在父卡的气泡/列表里改批注」与「在该子摘录卡上看到的批注」是**同一行同一列**——同步是结构性的，**不得**写任何同步逻辑。
- 删除批注 ＝ 删除那条摘录（`extracts:delete`，软删）。**UI 必须二次确认**并写明"会同时删掉这条摘录"（它是 R7 的直接后果）。

### 1.2 三种锚（都在既有列里）

| 情形 | 批注所在行 | 锚 | 落地位置 |
|---|---|---|---|
| 原文侧批注 | **根摘录**（`parentType='document'`） | `contextRef.sourceAnchor`（PDF `rects[]` 百分比 / EPUB `cfi`，批 3 已落） | 阅读器（原文） |
| 卡内批注（选段） | **子摘录**（`parentType='extract'`） | `contextRef.parentRange`（**父卡坐标**字符区间，工单 ② 已落） | 父卡的卡面（摘录页） |
| 卡自身的批注 | 该子摘录自己（＝它被创建时写的那条） | **整卡**（无区间） | 它自己的卡面（摘录页） |

### 1.3 层级规则（R25）

- 摘录页的批注栏**列出当前显示卡的全部直接条目**：`(a)` 它的"自身批注"（锚在整卡，＝它被创建时写的 comment）＋ `(b)` 卡内选段新建的子摘录（锚在段；含未写批注的纯高亮）。
- `(a)` 与 `(b)` 用**不同样式**（§5.3/§5.4）：`(a)` 恒置顶 + 整卡主题色高亮；`(b)` 左竖线＝其文中高亮同色 + 文中角标。
- 更深层（孙）**不在当前卡上显示**，只在那张子卡自己的页面上出现——这是"不是同一层级要区别开"的机械实现。

---

### 1.4 高亮与摘录分族（R35）

**同一张 `extracts` 表，加一列 `kind`**（`'highlight' | 'extract'`，默认 `'extract'` 以保存量语义）：

| | `kind='highlight'`（纯高亮） | `kind='extract'`（摘录） |
|---|---|---|
| 进复习队列 / 计每日上限 / 进 FSRS | **否** | 是（现有行为不变） |
| 卡片浏览器 / 全库搜索 | **是**（用户裁定） | 是 |
| 高亮（`sourceAnchor`/`parentRange`） | 有 | **必有**（摘录必带高亮） |
| 批注文字（`comment`） | 可选 | 可选 |
| 颜色（`annotation_color`） | 有 | 有 |

**机械后果（必须同步改的地方，逐条点明）**：
- 复习队列与四类每日计数一律加 `kind='extract'` 过滤（`listDueExtracts` / `usage` 派生 / `sessionQueue`）；**这是本轮唯一会动到既有调度链的地方**，回归必须覆盖 `extracts.test` 137 条里与队列/计数相关的断言。
- 卡片浏览器与全库搜索**不再过滤 kind**（默认就查全部），加类型列/筛选即可。
- **迁移**：`ALTER TABLE extracts ADD COLUMN kind TEXT`（列已存在即跳过，§7.2 既有纪律）；存量行 `COALESCE(kind,'extract')` 一律按摘录对待（零语义变更）；新写入由调用方显式给 kind。
- **降级/升级是纯改列**：删摘录但留高亮＝`kind: 'extract' → 'highlight'`；纯高亮转为摘录＝反向。**删除**才清行（R36）。

## §3 选区链路（摘录页与阅读器共用）

### 3.1 共用件

- `src/components/SelectionMenu.tsx`（新）：菜单本体 + 定位（§3.2）＋ 菜单项由宿主传入。
- `src/lib/popoverPlace.ts`（新，纯函数）：`placePopover({ anchor, container, size, prefer })` → `{left, top, placement}`。MarkPopover（批 3）与 SelectionMenu、AnnotationEditor 三处共用**同一份**放置实现（先渲染在视口外一帧 → `useLayoutEffect` 实测 → 夹紧）。
  - `prefer`：`"above" | "below" | "auto"`；`auto` 判据＝`anchor.centerY < container.top + container.height/2` → **below**（选区在上半，菜单在下），否则 **above**。
  - 越界：prefer 侧放不下 → 翻到另一侧；两侧都放不下 → 夹进容器（左右同理，8px 边距）。

### 3.2 菜单定位判据（R22，可测）

1. 菜单矩形**不得与选区包围盒相交**（菜单不得盖住选中文字）；
2. 菜单整体在阅读容器内（含 8px 边距）；
3. 选区在容器上半 → 菜单在选区**下方**；下半 → **上方**；
4. 锚点用**选区包围盒**，不再用 pointerup 坐标。

### 3.3 选区菜单（R38 重排）

菜单为**两行面板**（`position: fixed`，定位判据同 §3.2）：

| 行 | 内容 | 行为 |
|---|---|---|
| 第一行 | **模式段控**：`高亮` ｜ `摘录+高亮` | 互斥两枚（Zotero 页签同规：当前项 accent 下划线）；**状态持久**（`app.annotateMode`） |
| 第一行 | **调色排**：用户配好的色板 + 「自定义…」 | **点色即完成**当前模式的动作（高亮＝只建高亮；摘录+高亮＝建摘录并高亮）；**颜色不记**（每次选色都是一次明确动作） |
| 第二行 | `制卡` / `AI 制卡` / `AI 解释` / `查词` / `精细编辑…（写批注）` | 既有动作原样（`精细编辑…` 打开 §3.5 浮层写批注） |

> 用户 2026-09-27 更正：**颜色不记**（早先"连颜色一起记"的口径作废）。模式记得、颜色不记——这样"切换模式 → 选文字 → 点色"三步就是一次完整操作。

### 3.3b 菜单项与高亮

- 阅读器：`制卡 / AI 制卡 / AI 解释 / 摘录 / 查词 / 图片挖空`（既有六项）+ **`批注`**。
- 摘录页：`制卡 / AI 制卡 / AI 解释 / 摘录 / 查词` + **`批注`**（无图片挖空：卡面正文的图片能力属批 5）。
- 选区高亮＝CSS Custom Highlights（`::highlight(multi-select)`；宿主文档吃 `src/theme.css`，iframe 由 adapter 注入字面值）——**两处都不得往 DOM 插 `<mark>`**（`EditableText` 是"React 不接管子节点"的裸壳）。

### 3.4 「批注」动作

| 宿主 | 落库 |
|---|---|
| 阅读器 | `workflowAPI.create({ parentType:'document', documentId, contentMarkdown: 所选文字, comment: 输入文字, spans?, contextRef: {…, sourceAnchor} })`（sourceAnchor 采集沿用批 3） |
| 摘录页 | `workflowAPI.create({ parentType:'extract', parentId: 当前卡 id, documentId, contentMarkdown: 所选文字, comment: 输入文字, contextRef: {…, parentRange: 所选区间} })`（parentRange 采集沿用 `selectionOffsetsInBody`） |

- **编辑判定**：若实时选区与某条既有批注的锚（`parentRange` / `sourceAnchor.rects` 对应的字符区间）**完全一致** → 该菜单项显示为「编辑批注」，点开直接编辑那一条（不新建）。
- 输入 UI＝`src/components/AnnotationEditor.tsx`（新，小浮层），**按 R37 重设计**：
  - **无「保存」「取消」按钮**：`textarea` 输入**即时生效**（失焦 + 400ms 防抖落库，与本项目"编辑即写"一致）；浮层内显示保存态（`已保存` / `正在保存…`）。
  - **批注文字清空 ＝ 删除批注**（`comment → ''` → 写 `null`）：**条目本身保留**（纯高亮仍是高亮、摘录仍是摘录），并在浮层里明示「清空文字＝删除批注」。
  - **颜色方块按钮**：显示当前高亮色；点开列出**用户在设置里配好的色板**（§9.2）＋**自定义取色**（`<input type="color">`）；选色即时落库。
  - **删除按钮按类型换标签（R36）**：`kind='highlight'` → 「**删除高亮**」（清高亮+批注，整条消失）；`kind='extract'` → 「**删除摘录**」（高亮、摘录、批注一起清掉）。两者都带一次就地确认（焦点默认「取消」，D50 既有先例）。
  - 焦点陷阱 + `Esc` 关闭（`useDialogA11y` 既有件）。

## §5 批注的展示（两形态 + 批注栏）

### 5.1 唯一形态：`badge`（Zotero 式；R23/R31）

> 原「旁注气泡 + 发丝线」形态（用户 2026-09-27 第二轮提出、第四轮否决）**已删除**：用户裁定其效果不理想。
> 本规格与样张不再包含发丝线、气泡、以及任何形态开关——**只有这一种展示方式**。

### 5.2 文中痕迹（角标）

- 文中高亮的**右上角**加一枚**与高亮同色**的小便利贴角标（直角方块 + 缺角，形状而非字符；尺寸 `var(--sp-2)`）。
  - **画法硬约束（样张实测）**：角标**不得**用「高亮元素内 `position:absolute; right:0; top:0`」实现——高亮是 `inline` 元素，`inline` 包含块会把绝对定位子元素放到**联合包围盒**右上角，跨行高亮实测偏 **259px**；必须按 `getClientRects()[0]`（**首行片段**）的右缘/顶缘，画在宿主覆盖层里（与发丝线同一层、同一套重算），并随滚动/缩放/换卡重画。
- **点高亮**（不点角标也生效）→ 弹出 `AnnotationEditor`（改 / 删）。
- 右侧栏＝**Zotero 式批注列表**（§5.3）。

### 5.3 批注栏（Zotero 式列表，R24/R28）

- 列表项：**左竖线 + 色点 + 所引原文（截断）+ 批注文字 + 时间（mono, tabular-nums）**。
- **整卡批注恒置顶（R32，任何排序下都成立）**：它是"本条是什么"的元批注，层级高于卡内所有段锚批注。
- **整卡批注整卡高亮（R32）**：条目**整块**用 `--accent-soft` 底 + 左缘 2px `--accent`，色点用 `--accent`，带「本条批注 · 锚在整卡」标签。
- **段锚批注左竖线＝文中高亮同色（R33）**：竖线 2px 实色（`--annot-*`），文中高亮＝该 token 的透明档（`--annot-*-soft`：浅档 12% / 深档 26%）；
  两者同色相、不同不透明度——用户据此把栏内条目与文中那段对上。色点用同一实色。
- **纯高亮**：竖线仍用它自己的颜色，批注文字位显示「（未写批注）」，**不画角标**。
- **两类可辨（R39）**：摘录＝**实心**方点 + 「摘录」标签；纯高亮＝**空心**方点 + 「高亮」标签（不靠颜色区分，颜色已被批注色占用）。
- **筛选（R39）**：栏顶段控「全部 / 摘录 / 高亮」，默认全部；纯前端过滤，零写库。
- **点击条目 → 文中滚动到锚点并短暂强调**（高亮闪一下，1.6s，同既有落点做法）。
- **栏内可增 / 删 / 改**：条目内联编辑批注文字（失焦保存）；删除带就地二次确认（焦点默认「取消」）。
- **颜色**：条目上的色点可点 → 8 色板下拉（复用 `.dd`）；写入 `annotation_color`，角标/高亮/色点跟随。
- **排序**：按位置（默认）/ 按时间，二档切换（`app.annotationSort`? **不新增键**——排序是会话内视图偏好，存组件内 state；理由：与内容无关、不需要跨重启）。
- **栏内列出什么**：**全部注解**——含没写文字的纯高亮（与 Zotero 一致）；纯高亮用中性竖线 + 「（未写批注 · 纯高亮）」，**不画角标**。

### 5.4 层级样式（R25，机械判据）

| 类型 | 判据 | 栏内（列表项） | 文中 |
|---|---|---|---|
| 锚在整卡（自身批注） | 无区间 | **恒置顶**；整块 `--accent-soft` 底 + 左缘 2px `--accent`；色点 `--accent`；带「本条批注 · 锚在整卡」 | **不画角标** |
| 锚在某段（卡内选段） | 有区间 | 左竖线 2px ＝ 该批注色实色（`--annot-*`）；色点同色 | 高亮＝该色透明档（`--annot-*-soft`）；首行片段右上角贴同色角标 |
| 纯高亮（未写批注） | 有区间 | 左竖线 `--border-strong`（中性）；标注「（未写批注 · 纯高亮）」 | 高亮用其色板透明档，**不贴角标** |

### 5.5 由样张实测得到的硬约束（实现时不得再犯）

- **不得并行渲染两套侧栏（R31 后只有一套）**：早先「两形态」方案实测过「两个类并存」会让两套侧栏同时渲染、占位算成 378px——任何「按开关并行渲染两套」的写法都会重犯，审查时按这条判。
- **绘制层必须与数据一致且幂等**：重算 / 量测 / 换卡后一律**全量重画**（角标、覆盖层同进同出）。样张实测踩过「留下上一步残留」（角标与列表不一致）——绘制函数必须**幂等 + 全量重画**，禁止增量打补丁。

## §6 布局与窗口（R26/R27）

- 栏**出现条件**：当前显示对象至少有一条**注解**（摘录或纯高亮，含未写批注的）；摘录页＝有才出现，阅读器侧栏常驻（§7.1）。
- 出现即**占位**：**两个宿主都占**——摘录页＝正文列左移 280px（版心 720 在剩余区域内居中）；阅读器＝引擎视口右缩 280px（原文排版宽度随之变化，滚动位置不变）。
- `electron/main.js` 的 `BrowserWindow` 加 **`minWidth: 1120`**（720 版心 + 280 栏 + 两侧内边距 + 滚动条实测能容），另加 `minHeight: 640`。
- 窄窗不再退让（因为窗口不能小于 1120）。

## §7 阅读器（原文侧）

### 7.1 共用侧栏（R34）

- 右侧一个侧栏，顶部**三页签**：**目录 / 摘录(注解) / 图谱**；**同一时刻只有一个面板可见**；当前页签用 `--accent` 文字 + 2px accent 下划线（Zotero 同规）。
- **「摘录」页签**＝§5.3 的批注栏（本轮统一叫法：注解列表；含纯高亮）。
- **「图谱」页签**＝**仅当该材料存在图谱时显示**（`material_maps` 里该文档有活跃版；无图谱＝不渲染该页签，不做空态页签）。
- 侧栏**常驻**（阅读器是长驻阅读界面，不再用"有注解才出现"那条——那条只适用于摘录页的卡面）。

### 7.2 图谱页签＝图谱数据的目录化展示（R34）

- **数据面**：`electron/mindmapCore.js` 的 `buildExtractionModel` 已给出
  `nodeRange`（节点覆盖的**单元区间**，子区间**嵌套**于父）与 `ownedRanges`（父范围**减去**子范围＝父的自有区间，**严禁字符串减法**）。
  渲染层只消费这两者，**不得**自行切分区间（唯一实现面纪律）。
- **展示**：目录树（层级缩进）+ 每节点一行：**标题 + 自有区间 + 占比条**（宽度＝自有区间 ÷ 全书单元数）。
- **不重叠**：由区间差保证同级自有区间两两不相交；**点击节点 = 跳到该节点自有区间的起点单元**（复用既有导图跳转）。
- **不做**（本轮）：图谱页签里不提供制卡/编辑（那些在导图工作区里）；不做拖拽重排、不做区间并集视图。

- **内核新增可选能力** `getDocumentMarkRects(): { id: string; rect: ReaderRect }[]`：PDF＝覆盖层元素的实时矩形；EPUB＝Range 的 `getClientRects()` 转宿主坐标（沿用 `pointerToHost`）。外壳用它画发丝线、把栏与文中位置对上。
- 栏的出现条件、颜色、排序与摘录页同规；阅读器侧栏**常驻**并按 §7.1 分页签。
- 阅读器侧**批注的增 / 删 / 改**：新建＝选区菜单「批注」（§3.4）；改/删＝**点标记弹 `AnnotationEditor`**（唯一入口，与摘录页同规）。
- **指针语义（写死防漂）**：hover 浮层保留（原文 + 批注 + 已制卡数 + 「就此制卡」——它与批注编辑是两件事）；**点击标记＝打开 `AnnotationEditor`**（改 / 删批注）；批 3 的"点标记钉住浮层"由本条取代。
- **不做**：阅读器侧不显示孙层批注（同 §1.3）；原文侧的"锚在整卡"类型不存在（原文侧注解都锚在文档上）。
